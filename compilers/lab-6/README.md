## Немного теории

Язык разметки — это набор управляющих последовательностей, которые вставляются в текст
и говорят, как этот текст устроен или как его показывать. У документа три составляющие:
содержание, структура и внешнее представление. Отсюда два вида разметки:

- **структурная** — что это за часть текста (`<head>`, `<p>` — заголовок, абзац);
- **разметка представления** — как её показать (шрифт Arial 16, отступ 20, красный цвет).

Многие языки разметки имеют блочную структуру: документ — блок, который состоит из блоков,
которые состоят из блоков, и так далее. Разметку обычно задают **тегами** — ключевыми словами
в угловых скобках. Пара `<tag> … </tag>` работает как логические скобки, а атрибуты тега
(`color=red`) задают параметры представления.

eMark — язык именно разметки представления: он описывает, как разрезать экран консоли 24×80
на прямоугольники и что, где и какими цветами в них вывести. Процессор такого языка устроен
как маленький компилятор: лексический анализ → синтаксический анализ (дерево) → семантические
проверки → «генерация кода», только вместо машинного кода получается картинка на экране.

## Язык eMark

### Как его понимает процессор

Три тега:

| Тег | Атрибуты | Что делает |
| --- | --- | --- |
| `<block>` | `rows`, `columns` | прямоугольник, который делится на строки и/или столбцы |
| `<column>` | `valign`, `halign`, `textcolor`, `bgcolor`, `width` | столбец блока шириной `width` символов |
| `<row>` | `valign`, `halign`, `textcolor`, `bgcolor`, `height` | строка блока высотой `height` строчек консоли |

- `valign` — `top` | `center` | `bottom`, `halign` — `left` | `center` | `right`;
- `textcolor`, `bgcolor` — число 0–15 (см. таблицу цветов ниже);
- `width`, `height` — целое больше нуля; `rows`, `columns` — целое не меньше нуля.

Ограничения из методички и как они проверяются:

1. В документе хотя бы один `<block>`. Каждый `<block>` верхнего уровня занимает весь экран
   24×80; если блоков верхнего уровня несколько, они выводятся друг за другом как отдельные экраны.
2. `rows` и `columns` обязательны и не больше высоты (ширины) элемента, в который блок вложен.
3. Количество `<column>` и `<row>` в блоке равно `columns` и `rows`.
4. Умолчания: `valign=top`, `halign=left`, `textcolor=15`, `bgcolor=0`. `width` можно не писать
   только у последнего `<column>` блока: ему достаётся ширина блока минус сумма предыдущих.
   С `height` у последнего `<row>` так же. `columns=1` и `rows=0` подставляются только для
   внешнего блока, у вложенных оба атрибута обязательны.
5. У каждого тега есть закрывающий.

### Грамматика

Спецификация в методичке словесная, поэтому записал грамматику сам (то, что проверяется
контекстно — количество тегов и размеры, — в ней в виде комментариев):

```
документ  : блок {блок}
блок      : '<block' атрибуты '>' содержимое_блока '</block>'
содержимое_блока
          : столбец {столбец}            ; если rows = 0: ровно columns штук
          | строка {строка}              ; если rows > 0: ровно rows штук
строка    : '<row' атрибуты '>' (ячейка | столбец {столбец}) '</row>'
                                         ; столбцы — если у блока columns > 0, ровно columns штук
столбец   : '<column' атрибуты '>' ячейка '</column>'
ячейка    : текст | блок                 ; текст или ровно один вложенный блок
атрибуты  : {имя '=' значение}
значение  : слово | '"' символы '"' | "'" символы "'"
```

### Спорные места и как они решены

**Семантика вложенности.** Пример с рис. 1 в методичке идёт *до* спецификации eMark и показывает
общую идею: там `<row>` лежит прямо в `<column>`, а `<column>` — прямо в `<row>`, у блоков нет
атрибутов, а у внешнего блока два столбца при умолчании `columns=1`. Листинг не сходится
и сам с собой: `C` и `D` лежат прямо в блоке между строками, а последняя `<row></row>` пустая;
на картинке же `A` — подпись над вложенным блоком, а справа от `B` пустая клетка. По правилам
eMark этот пример некорректен (процессор так и говорит, см. `err_10_methodology`). Я принял схему,
согласованную с атрибутами `rows`/`columns`:

- `rows=0, columns=C` — блок делится на C столбцов, каждый во всю высоту блока
  (так устроен внешний блок по умолчанию: один столбец на весь экран);
- `rows=R, columns=0` — блок делится на R строк, каждая во всю ширину;
- `rows=R, columns=C` — сетка: R строк, и **в каждой** строке ровно C столбцов. Ширины столбцов
  в разных строках задаются отдельно, так что это не жёсткая таблица;
- `rows=0, columns=0` — ошибка: блок не на что делить.

Блок всегда занимает всю ячейку, в которой лежит. Ячейка (`<column>` или `<row>` без столбцов)
содержит либо текст, либо ровно один `<block>`; чтобы поделить ячейку дальше, в неё вкладывают
новый блок. Тогда структура из листинга рис. 1 (сетка A B / C D, под ней F, справа E) на eMark
выглядит так (`examples/02_nested.emark`):

```
<block rows=0 columns=2>
	<column width=50>
		<block rows=2 columns=0>
			<row height=16>
				<block rows=2 columns=2>
					<row height=8>
						<column width=25 bgcolor=1>A</column>
						<column bgcolor=2>B</column>
					</row>
					<row>
						<column width=25 bgcolor=3>C</column>
						<column bgcolor=4>D</column>
					</row>
				</block>
			</row>
			<row bgcolor=5>F</row>
		</block>
	</column>
	<column bgcolor=6 textcolor=14>E</column>
</block>
```

**Наследование стиля.** `valign`, `halign`, `textcolor`, `bgcolor`, не указанные у ячейки, берутся
у объемлющей ячейки (у столбца — от строки, у ячейки во вложенном блоке — от ячейки, где лежит блок).
Значения из п. 4 — это умолчания для самого верхнего уровня. Иначе `<row bgcolor=1>` со столбцами
внутри перекрашивался бы обратно в чёрный, что противоречит здравому смыслу.

**Текст и кавычки.** В простейшем примере текст `”Hellow world” example using eMark` начинается
с кавычки, но закрывающая кавычка стоит в середине, то есть кавычки — часть фразы, а не
ограничители строки. Поэтому кавычки (любые) — обычные символы и выводятся как есть. Текст — всё
между тегами; подряд идущие пробелы, табуляции и переводы строк сворачиваются в один пробел, как
в HTML, поэтому документ можно спокойно форматировать отступами. Символ `<` в тексте невозможен:
он всегда начинает тег. Файл читается в UTF-8; BOM в начале (так сохраняет Блокнот) пропускается.

**Перенос и обрезка.** Текст переносится по словам на ширину ячейки. Слово длиннее ширины
режется на куски по ширине. Если строк больше, чем высота ячейки, лишние снизу отбрасываются,
и процессор пишет **предупреждение** (не ошибку — экран всё равно выводится).

**Свободное место.** Если у последнего столбца (строки) ширина (высота) задана явно и в сумме
меньше блока, остаток блока остаётся пустым и закрашивается фоном объемлющей ячейки.
Если сумма больше — ошибка.

**Атрибуты.** Значение можно писать без кавычек (`rows=2`) или в кавычках (`rows="2"`, `rows='2'`),
пробелы вокруг `=` допустимы. Имена тегов и атрибутов — строчными буквами, как в методичке.
Повторный атрибут — ошибка. Атрибут, которого нет у этого тега (`height` у `column`), — ошибка.

### Цвета

Номера 0–15 — палитра текстового режима PC (CGA/EGA), та самая, что в `textcolor()` Turbo C
и в консоли Windows. В ANSI-терминале порядок первых восьми цветов другой (у ANSI 1 — красный,
4 — синий), поэтому номер переставляется по таблице, а 8–15 выводятся «яркими» кодами 90–97/100–107.

| eMark | Цвет | ANSI текст / фон | eMark | Цвет | ANSI текст / фон |
| ---: | --- | --- | ---: | --- | --- |
| 0 | чёрный | 30 / 40 | 8 | тёмно-серый | 90 / 100 |
| 1 | синий | 34 / 44 | 9 | светло-синий | 94 / 104 |
| 2 | зелёный | 32 / 42 | 10 | светло-зелёный | 92 / 102 |
| 3 | бирюзовый | 36 / 46 | 11 | светло-бирюзовый | 96 / 106 |
| 4 | красный | 31 / 41 | 12 | светло-красный | 91 / 101 |
| 5 | пурпурный | 35 / 45 | 13 | светло-пурпурный | 95 / 105 |
| 6 | коричневый | 33 / 43 | 14 | жёлтый | 93 / 103 |
| 7 | светло-серый | 37 / 47 | 15 | белый | 97 / 107 |

Цвет 6 в ANSI обычно показывается тёмно-жёлтым — это и есть «коричневый» CGA.

## Как запустить

Python 3.14, только стандартная библиотека; интерпретатор уже есть в `flake.nix`.

```bash
# один раз, в корне репозитория (.envrc с `use flake`)
cd ~/repos/uni
direnv allow

cd compilers/lab-6
python3 main.py examples/02_nested.emark              # в цвете
python3 main.py --no-color examples/02_nested.emark   # без цвета
python3 main.py --no-color --frame examples/03_align.emark   # с рамкой экрана 80x24
python3 tests.py                                      # прогон всех примеров
```

Без direnv: `nix develop -c python3 main.py examples/01_hello.emark` из папки лабы.

Опции:

- `--no-color` — без escape-последовательностей (для файлов и тестов), хвостовые пробелы
  строк обрезаются;
- `--frame` — рамка `+---+` вокруг экрана, чтобы видеть границы 80×24 и выравнивание
  по правому/нижнему краю.

Коды возврата: 0 — документ выведен, 1 — в документе ошибки, 2 — неверные аргументы
или файл не читается.

## Архитектура

Всё в одном файле [`main.py`](main.py) (~530 строк), четыре этапа идут друг за другом:

```
текст ──► tokenize ──► parse ──► Layout.place_block ──► render ──► консоль
          токены       дерево    буфер 24x80 + проверки   ANSI / без цвета
```

1. **Лексер** `tokenize` проходит по тексту один раз и выдаёт токены трёх видов: открывающий тег
   (имя + словарь атрибутов с позициями), закрывающий тег, текст. Всё до ближайшего `<` — текст.
   Позиции хранятся как индекс; номер строки и столбца считается двоичным поиском по массиву
   начал строк. После ошибки в теге лексер пропускает всё до `>` и продолжает, поэтому
   лексические ошибки выдаются все сразу.
2. **Парсер** `parse` строит дерево `Node` на стеке: открывающий тег кладётся на стек и становится
   ребёнком вершины, закрывающий должен совпасть с вершиной и снимает её. Здесь проверяется
   парность тегов (ограничение 5), неизвестные теги и текст не на своём месте. Ошибка парности
   останавливает разбор: дальше дерево уже не соответствует замыслу автора.
3. **Раскладка** `Layout` рекурсивно проходит дерево сверху вниз. Размер блока становится известен
   только здесь (он равен ячейке родителя), поэтому здесь же проверяются атрибуты, количество
   `column`/`row` и размеры (ограничения 1–4). `split` делит ширину или высоту блока между
   столбцами или строками, подставляя остаток последнему. `place_cell` закрашивает ячейку фоном
   и рисует текст (`wrap` + выравнивание) или раскладывает вложенный блок в её прямоугольник.
   Рисуется сразу в буфер экрана — список 24×80 клеток `[символ, цвет текста, цвет фона]`.
   Если нашлась хоть одна ошибка, буфер просто не печатается.
4. **Вывод** `render` печатает буфер: в цветном режиме вставляет escape-код только там,
   где меняется пара цветов, и сбрасывает цвет в конце строки.

Выравнивание: для `valign` отступ сверху равен 0, `(h − n) // 2` или `h − n`, где n — число строк
текста; для `halign` то же по ширине для каждой строки отдельно.

## Обрабатываемые ошибки

Формат сообщения: `файл:строка:столбец: вид: текст`. Все сообщения сортируются по позиции.

| Вид | Ошибка |
| --- | --- |
| лексическая | после `<` нет имени тега |
| | тег не закрыт символом `>` до конца файла |
| | у закрывающего тега есть атрибуты |
| | неожиданный символ внутри тега |
| | после имени атрибута нет `=`; у атрибута нет значения; не закрыта кавычка |
| | атрибут указан повторно |
| синтаксическая | неизвестный тег |
| | закрывающий тег не соответствует открытому / закрывающий без открывающего |
| | тег не закрыт до конца файла |
| | в документе нет ни одного `<block>`; на верхнем уровне не `<block>` |
| | текст вне тегов или прямо внутри `<block>` |
| семантическая | у тега нет такого атрибута |
| | недопустимое значение `valign`/`halign`; не число; цвет больше 15; `width`/`height` = 0 |
| | у вложенного блока нет `rows` или `columns` |
| | `rows` больше высоты или `columns` больше ширины родителя; `rows=0` и `columns=0` |
| | число `<column>`/`<row>` не совпадает с атрибутом; в блоке тег не того вида |
| | нет `width`/`height` у непоследнего столбца/строки |
| | сумма размеров больше блока; последнему столбцу/строке не осталось места |
| | в ячейке одновременно текст и теги; в ячейке что-то кроме одного `<block>` |
| | строка блока с `columns > 0` состоит из текста |
| | слишком глубокая вложенность (сотни блоков друг в друге: раскладка рекурсивная) |
| предупреждение | текст не поместился по высоте и обрезан |

Лексические ошибки собираются все, затем разбор останавливается. Синтаксические ошибки парности
останавливают разбор сразу; «текст не на месте» разбор не останавливает. Семантические ошибки
собираются по всему дереву; если у блока неправильно задано деление (например, нет `width`),
внутрь этого блока проверка не заходит — ошибки там будут видны после исправления.
