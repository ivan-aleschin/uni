## Задание

Создать интерпретатор языка CBAS.

- Входные данные: исходный текст программы на языке CBAS.
- Выходные данные: консоль с результатами ввода-вывода исходной программы либо сообщения
  об ошибках, присутствующих в программе.

Методичка отдельно требует работать с **внутренним форматом лексем**: каждой лексеме
присваивается номер, и интерпретатор сравнивает числа, а не строки. Также нужна функция
получения очередной лексемы и возможность вернуть лексему обратно во входной поток.

## Язык CBAS

CBAS — смесь BASIC и C, упрощённая почти до предела. Грамматика из методички (повторения
`<id_end>`/`<number_end>` записаны короче через `{}`):

```
<identifier>      : <character> {<character>}         ; латинские буквы и '_', без цифр
<number>          : <digit> {<digit>}                 ; только неотрицательные литералы
<expression>      : <term> '+' <expression> | <term> '-' <expression> | <term>
<term>            : <factor> '*' <term> | <factor> '/' <term> | <factor>
<factor>          : <identifier> | <number> | '(' <expression> ')'
<relop>           : '<' | '>' | '==' | '!='
<bool_expression> : <expression> <relop> <expression>
<assign>          : <identifier> '=' <expression>
<string>          : '"' <любые символы, кроме '"'> '"'
<print>           : 'print' <print_end> ';'
<print_end>       : <string> | <expression> | <string> ',' <print_end> | <expression> ',' <print_end>
<scan>            : 'scan' <identifier> ';'
<for>             : 'for' <identifier> '=' <expression> 'to' <expression>
<if>              : 'if' <bool_expression>
<else>            : | 'else' '{' <statement> '}'
<statement>       : | <print> <statement> | <scan> <statement> | <assign> <statement>
                    | <for> '{' <statement> '}' <statement>       ; хвост <statement> — см. ниже
                    | <if> '{' <statement> '}' <else> <statement>
<program>         : <statement>
```

Своими словами:

- **Переменные** глобальные, без объявлений, тип — `int`. Таблица переменных — пары
  «имя — значение»; встретив новое имя, интерпретатор заводит его со значением 0.
- **`x = выражение`** — присваивание. Выражения: `+ - * /`, скобки, обычные приоритеты.
- **`print элемент, элемент, …;`** — печать строк и значений выражений.
- **`scan x;`** — ждёт, пока пользователь введёт целое число, и кладёт его в `x`.
- **`for i = a to b { ... }`** — `i` получает значение `a`, увеличивается на 1 после каждой
  итерации; выход, когда `i` больше или равна `b`.
- **`if условие { ... } else { ... }`** — `else` необязателен, условие — одно сравнение.

Комментариев, `while`, `goto`, подпрограмм, логических `and`/`or`, унарного минуса в CBAS нет,
поэтому их нет и в интерпретаторе. Реализовано всё из спецификации и ничего сверх неё, кроме
необязательной `;` после присваивания (см. «Спорные места»).

### Спорные места спецификации и как они решены

| Вопрос | Решение |
| --- | --- |
| В методичке `<statement>: … \| <for> '{' <statement> '}'` — после цикла и `if` нет хвостового `<statement>`, то есть они могли бы стоять только в конце программы | Считаю опиской: после `}` программа продолжается, как после `print` или `scan` |
| Нужна ли `;` после присваивания? В грамматике её нет | Не нужна, как в грамматике (`a = 1 b = 2` — корректно). Но если поставить — тоже не ошибка: люди пишут `x = 5;` по привычке из C |
| Грамматика `<expression>: <term> '-' <expression>` правоассоциативна: `10-5-2` дала бы `10-(5-2) = 7` | Реализованы правила из раздела «Порядок построения выражений»: `Выражение => Терм [+Терм][-Терм]` — цикл, левая ассоциативность, `10-5-2 = 3` |
| Проверяется ли условие `for` до первой итерации? | Да: «выход, когда переменная больше или равна границе» проверяется перед каждой итерацией, как в C `for (i = a; i < b; i++)`. `for j = 5 to 5` не выполняется ни разу |
| Когда вычисляется граница `for`? | Один раз при входе (в методичке она хранится в стеке как `target`) |
| Что печатает `print a, b`? | Элементы подряд без разделителей, в конце перевод строки |
| Деление `int` | Как в C: дробная часть отбрасывается к нулю, `(0-7)/2 = -3` |
| «Тип аналогичный int» | Значения ограничены 32 битами; выход за них — ошибка выполнения «переполнение int» |
| Ввод не числа в `scan` | По методичке выполнение стоит, «пока пользователь не введёт какое-либо число»: интерпретатор пишет предупреждение и ждёт следующее число. Если ввод закончился — ошибка выполнения |
| Стек циклов `for_stack` | Методичка разрешает вместо явного стека рекурсию: «информация сохраняется в локальных переменных вызывающей процедуры». Так и сделано: `process_for` хранит переменную, границу и место начала тела в своих локальных переменных |

## Внутренний формат лексем

Функция `Lexer.get_token()` ([lexer.py](lexer.py)) берёт из текста очередную лексему и возвращает
`Token(code, text, value, line)`: `code` — внутренний номер, `text` — внешний формат (нужен только
для сообщений об ошибках), `value` — значение числа, текст строки или имя переменной, `line` —
номер строки. Ключевые слова ищутся в таблице `KEYWORDS` (аналог `struct commands table[]`
из методички), разделители — в таблице `DELIMITERS`.

По диапазону номера сразу понятен тип лексемы (функция `kind()`): ключевое слово, лексема
со значением или разделитель.

| Номер | Лексема | Номер | Лексема | Номер | Лексема |
| --- | --- | --- | --- | --- | --- |
| 0 | конец программы | 20 | `+` | 28 | `=` |
| 1 | `print` | 21 | `-` | 29 | `<` |
| 2 | `scan` | 22 | `*` | 30 | `>` |
| 3 | `for` | 23 | `/` | 31 | `==` |
| 4 | `to` | 24 | `(` | 32 | `!=` |
| 5 | `if` | 25 | `)` | 33 | `,` |
| 6 | `else` | 26 | `{` | 34 | `;` |
| 10 | переменная | 27 | `}` | | |
| 11 | число | | | | |
| 12 | строка | | | | |

Пример: `for i = 1 to 10 { print "x", i; }` превращается в
`3 10 28 11 4 11 26 1 12 33 10 34 27 0` (это проверяет тест `test_internal_format`).

Весь текст переводится во внутренний формат один раз перед запуском (`tokenize`), дальше
интерпретатор ходит по списку лексем указателем `pos` — это аналог `char* location`
из методички. `get_token()` интерпретатора сдвигает указатель вперёд, `putback()` — на одну
лексему назад («вернуть лексему во входной поток»). Чтобы повторить тело цикла, указатель
просто ставится обратно на его начало.

## Выражения: рекурсивный спуск

Правила из методички с квадратными скобками, которые на деле означают «повторить сколько угодно раз»:

```
Выражение => Терм {('+' | '-') Терм}
Терм      => Фактор {('*' | '/') Фактор}
Фактор    => Переменная | Число | '(' Выражение ')'
```

Каждому правилу соответствует функция: `expression()`, `term()`, `factor()`. Приоритет
задаётся самой вложенностью: `*` и `/` разбираются глубже (в `term`), поэтому выполняются раньше,
чем `+` и `-`. Скобки — это рекурсивный вызов `expression()` из `factor()`.

Разбор `9/3-(100+56)` из методички:

1. `expression` вызывает `term`, тот берёт фактор `9`, видит `/`, берёт фактор `3`, получает 3.
2. `term` видит `-` — не его операция, возвращает лексему (`putback`) и 3.
3. `expression` видит `-`, вызывает `term` → `factor` видит `(` и рекурсивно вызывает
   `expression`, которая возвращает `100+56 = 156`.
4. `expression` вычисляет `3 - 156 = -153`.

Условие `if` — отдельная функция `bool_expression()`: выражение, операция сравнения, выражение.

Устройство интерпретатора повторяет схему из методички. `statements()` — это `main_loop`:
берёт лексему и по её номеру (`match tok.code`) вызывает `process_print`, `process_if`,
`process_for` и т. д. Функции для `if` и `for` разбирают заголовок и снова вызывают
`statements()` для тела в фигурных скобках — так обрабатывается вложенность. `statements()`
возвращается, дойдя до `}` своего блока.

У каждой `process_*` есть флаг `ex` — «выполнять или только разобрать». Он нужен в трёх местах:

1. **Проверка синтаксиса до запуска.** `run()` сначала проходит программу с `ex=False`:
   ничего не печатается и не вводится, значения не вычисляются (`factor()` возвращает 0), но все
   конструкции разбираются. Синтаксическая ошибка
   в конце программы найдётся до того, как программа что-то напечатает или попросит ввод.
   Потом второй проход с `ex=True` — выполнение.
2. **Пропуск ветки `if`.** Невыполняемая ветка разбирается с `ex=False` — так указатель
   доходит до её закрывающей `}` с учётом любой вложенности. Деление на ноль или переполнение
   в такой ветке ошибкой не считается: она же не выполняется.
3. **Выход из `for`.** После последней итерации тело разбирается ещё раз с `ex=False`,
   чтобы встать за `}` (иначе при нуле итераций мы бы не знали, где кончается тело).

Цикл `for` в `process_for()`:

```python
body = self.pos                                  # начало тела
if ex:
    self.variables[name] = start
    while self.variables[name] < target:         # выход, когда переменная >= границы
        self.pos = body                          # вернуться к началу тела
        self.block(True)
        self.variables[name] = self.check_int(self.variables[name] + 1, var.line)
self.pos = body
self.block(False)                                # встать за '}'
```

`name`, `target` и `body` — локальные переменные вызова, то есть та самая запись
`for_stack {var, target, location}` из методички; стеком служит стек вызовов Python.

## Обрабатываемые ошибки

Формат сообщения: `Ошибка в строке N: …` (лексическая или синтаксическая — программа
не запускается) или `Ошибка выполнения в строке N: …` (программа успела выполниться до этого места).
Сообщение пишется в stderr, код возврата 1.

| Вид | Пример сообщения |
| --- | --- |
| имя с цифрой | `недопустимое имя 'x1': имя переменной состоит только из латинских букв и '_'` |
| чужой символ | `недопустимый символ '%'` |
| число и буква слитно | `недопустимая лексема '12ab'` |
| слишком большое число | `число 99999999999 не помещается в int (максимум 2147483647)` |
| незакрытая строка | `строка не закрыта кавычкой '"'` |
| `!` без `=` | `после '!' ожидалось '=' (операция '!=')` |
| нет `)` | `ожидалось ')', а встретилось разделитель ';'` |
| плохой операнд | `ожидалось число, переменная или '(', а встретилось разделитель ';'` |
| нет `}` | `'{' не закрыта: не хватает '}'` (строка открывающей скобки) |
| лишняя `}` | `лишняя '}' без парной '{'` |
| не оператор | `ожидался оператор (print, scan, for, if или присваивание), а встретилось число '5'` |
| `else` без `if` | `else без if (else пишется сразу после '}' блока if)` |
| условие без сравнения | `в условии ожидалась операция сравнения (<, >, ==, !=), а встретилось разделитель '='` |
| ошибки в заголовке `for`, `scan`, `print` | `ожидалось ключевое слово 'to', а встретилось число '10'`, `в print ожидалась ',' или ';', …` |
| деление на ноль | `Ошибка выполнения …: деление на ноль` |
| переполнение | `Ошибка выполнения …: переполнение int: результат 6227020800 не помещается в 32 бита` |
| ввод закончился | `Ошибка выполнения …: scan: ввод закончился, а число так и не введено` |
| слишком глубокая вложенность | `Ошибка: слишком глубокая вложенность скобок или блоков` (сотни уровней `(` или `{`: кончается стек вызовов Python — это аналог предела `FOR_COUNT` из методички) |

```
    prime = 1
    for d = 2 to p {
        if p - p/d*d == 0 { prime = 0 }
    }
    if prime == 1 {
        print p;
        count = count + 1
    }
}
print "Всего простых: ", count;
```

### Тесты

`tests.py` запускает `main.py` на каждом `examples/*.cbas` (ввод из `*.in`), сравнивает stdout
и stderr с `*.expected` и проверяет код возврата (`err_*` — 1, остальные — 0). Ещё три теста проверяют
лексер: номера лексем, двухсимвольные `==`/`!=` и номер строки в ошибке. Три последних — крайние
случаи интерпретатора: переполнение в невыполняемой ветке `if` не считается, `-2147483648 / (0-1)`
даёт ошибку переполнения, тысяча вложенных скобок — понятную ошибку, а не трейсбек Python.
