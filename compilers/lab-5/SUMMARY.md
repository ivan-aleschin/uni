# ЛР5. Интерпретатор CBAS — коротко

Шпаргалка «на пальцах». Полный отчёт — [README.md](README.md).

## Суть

CBAS — игрушечный язык: переменные `int` без объявлений, `print`, `scan`, `for … to`,
`if … else`, выражения с `+ - * /` и скобками. Интерпретатор не переводит программу в машинный
код, а сразу выполняет её, шагая по тексту. Текст сначала режется на лексемы, и каждая
получает **внутренний номер** (`for` = 3, `if` = 5, `+` = 20…), дальше всё сравнивается
по числам. Выражения считаются **рекурсивным спуском**: одна функция на одно правило грамматики.
Вложенные `for`/`if` — это рекурсивный вызов главного цикла для тела в `{ }`.

## Что делает программа

| Этап | Где | Что происходит |
| --- | --- | --- |
| Лексический анализ | `lexer.py`, `Lexer.get_token()` | текст → список `Token(номер, текст, значение, строка)`; ловит `x1`, `%`, незакрытую строку |
| Проверка синтаксиса | `run()`, проход с `ex=False` | вся программа разбирается, но ничего не выполняется |
| Выполнение | `run()`, проход с `ex=True` | те же функции, но теперь печатают, читают ввод, меняют переменные |
| Выражения | `expression → term → factor` | приоритет и скобки через вложенность вызовов |
| Ошибки | `CbasError` | `Ошибка в строке N: …` или `Ошибка выполнения в строке N: …`, код 1 |

## Вывод и откуда он

- `9/3-(100+56) = -153`: `term` считает `9/3 = 3`, `factor` на `(` рекурсивно зовёт `expression`
  (156), потом `3 - 156`.
- `10-5-2 = 3`, а не 7: сложение и вычитание идут **циклом** слева направо, а не правой рекурсией,
  как в BNF методички.
- `(0-7)/2 = -3`: деление как в C, к нулю. Унарного минуса в CBAS нет, поэтому `0-7`.
- `for i = 0 to 5` печатает 0..4, после цикла `i = 5`; `for j = 5 to 5` — ни одной итерации:
  условие «выйти, когда `i >= b`» проверяется до каждой итерации.
- `err_late.cbas` не печатает даже первую строку: синтаксическая ошибка в 3-й строке найдена
  на проходе проверки. А `err_div_zero.cbas` успевает напечатать две строки — это ошибка
  выполнения.
- `primes.cbas` с N = 30 — 10 простых чисел (2…29).

## Как рассказывать

> «Интерпретатор из трёх частей. Лексер переводит текст во внутренний формат: каждая лексема —
> номер из перечисления `Tok`, ключевые слова ищутся в таблице, как `commands table[]` в методичке.
> Интерпретатор идёт по списку лексем указателем: `get_token` берёт следующую, `putback` возвращает.
> Главный цикл `statements` смотрит на номер лексемы и вызывает `process_print`, `process_for` и т. д.;
> для тела в фигурных скобках они снова вызывают `statements`, так работает вложенность. Выражения —
> рекурсивный спуск: выражение из термов, терм из факторов, фактор — число, переменная или выражение
> в скобках. Программа проходится дважды: сначала только проверка синтаксиса, потом выполнение».

## Возможные вопросы

- **Зачем внутренний формат?** Сравнивать числа быстрее и проще, чем строки; к тому же номер сразу
  говорит тип лексемы (1–9 — ключевые слова, 10–12 — переменная/число/строка, 20+ — разделители).
- **Зачем `putback`?** Функция не всегда знает заранее, её ли это лексема. `expression` читает
  следующую лексему, и если это не `+`/`-`, возвращает её — дальше разберётся вызывающая функция.
- **Как задан приоритет операций?** Вложенностью: `*`/`/` обрабатываются в `term`, который вызывается
  из `expression`, поэтому они выполняются раньше `+`/`-`. Скобки — рекурсия из `factor`.
- **Где стек циклов из методички?** Методичка разрешает заменить его рекурсией. Переменная, граница
  и место начала тела — локальные переменные `process_for`, стек — стек вызовов Python.
- **Как пропускается ветка `if`, которая не выполняется?** Она разбирается той же функцией с
  `ex=False`: ничего не делается, но указатель доходит до её `}` с учётом вложенных блоков.
- **Зачем два прохода?** Чтобы синтаксическая ошибка в конце программы нашлась до того, как программа
  что-то напечатает или попросит ввод.
- **Откуда номер строки в ошибке?** Лексер считает `\n` и записывает строку в каждую лексему.
  Для незакрытой `{` выводится строка самой `{`.
- **Чего нет в CBAS?** Комментариев, `while`, `goto`, подпрограмм, `and`/`or`, унарного минуса,
  `<=`/`>=`. Цифр в именах тоже нет — `x1` даёт ошибку.

## Код по блокам

**Лексер, `lexer.py` (137–146 и 167–173) — внешний формат во внутренний:**

```python
137 if ch in LETTERS:                                  # РАЗВИЛКА: слово
138     while ... src[self.pos] in LETTERS:            # ЦИКЛ: читаем буквы
140     if ... src[self.pos] in DIGITS: raise ...      # x1 — ошибка
145     code = KEYWORDS.get(word, Tok.IDENT)           # ключевое слово или переменная
167 two = src[self.pos:self.pos + 2]                   # сначала двухсимвольные == и !=
171 if ch in DELIMITERS: ...                           # потом односимвольные
```

**Поток лексем, `interpreter.py` (38–45):**

```python
39 tok = self.tokens[min(self.pos, len(self.tokens) - 1)]   # за концом всегда END
40 self.pos += 1                                             # get_token: вперёд
45 self.pos -= 1                                             # putback: назад
```

**Главный цикл (55–91):** два прохода `statements(False)` и `statements(True)`; внутри
`while True` (ЦИКЛ) и `match tok.code` (РАЗВИЛКА) по номеру лексемы; `}` — конец блока,
`END` — конец программы.

**Цикл `for` (132–149):**

```python
138 target = self.expression(ex)                  # граница — один раз
139 body = self.pos                               # запомнили начало тела
143 while self.variables[name] < target:          # ЦИКЛ: выход при var >= target
144     self.pos = body                           # вернулись к началу тела
145     self.block(True)                          # выполнили тело
146     self.variables[name] = ... + 1            # шаг +1
148 self.pos = body; self.block(False)            # холостой проход — встать за '}'
```

**`if` (151–158):** `block(ex and cond)`, затем РАЗВИЛКА: если следующая лексема `else` —
`block(ex and not cond)`, иначе `putback()`.

**Рекурсивный спуск (180–229):**

```python
182 value = self.term(ex)                         # первый терм
183 while True:                                   # ЦИКЛ: + и - слева направо
185     if op.code == Tok.PLUS: value += term     # РАЗВИЛКА по операции
190     else: self.putback(); return value        # не наша лексема — вернуть
215 match tok.code:                               # factor: РАЗВИЛКА
222     return self.variables.setdefault(..., 0)  # новая переменная = 0
```

`term` (193–210) устроен так же для `*` и `/`, плюс проверка деления на ноль.
