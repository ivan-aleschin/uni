## Условие

Написать программу-аналог калькулятора. На входе произвольная строка символов, на выходе — заключение,
является ли она корректным арифметическим выражением, и его значение, а для некорректной строки — тип ошибки.

Распознаваемые лексемы:

1. знаки операций `+`, `-`, `*`, `/`;
2. скобки `(` и `)`;
3. действительные числа: `12`, `66.6`, `.54`, `221.`;
4. имя встроенной функции.

Задание максимум: вычислить значение с учётом приоритетов, обрабатывать исключительные ситуации
(деление на 0 и т. п.), поддержать одну встроенную функцию двух аргументов (например, `log(a, b)`),
аргументы которой сами являются выражениями, в том числе с этой же функцией. Функция должна
сравнительно просто заменяться (например, `log` → `pow`) и иметь наивысший приоритет.

## Алгоритм

Выбран метод из методички: перевод в обратную польскую запись (ОПЗ) по алгоритму Дейкстры
со стековыми приоритетами и вычисление ОПЗ на стеке. Но алгоритм Дейкстры сам по себе ошибок
не ловит: на `2+*3` или `2 3` он молча построит какую-то ОПЗ. Поэтому перед ним стоит отдельный
проход синтаксической проверки.

### Проверка синтаксиса

Корректное выражение — это чередование «операнд, операция, операнд, …», где операндом может быть
число, скобка с выражением или вызов функции. Поэтому при проходе по лексемам достаточно помнить,
**что сейчас ожидается**:

| Ожидаем | Допустимо | После этого ждём |
|---|---|---|
| операнд | число | операцию |
| | `-` (унарный минус) | операнд |
| | `(` | операнд |
| | `log` + обязательная `(` | операнд |
| операцию | `+ - * /` | операнд |
| | `)` | операцию |
| | `,` (только внутри скобок функции) | операнд |
| | конец строки | — |

Всё, что не попало в таблицу, — ошибка, и по тому, какая лексема стоит и какая была перед ней,
выбирается понятное сообщение («два знака операции подряд», «пустые скобки» и т. д.). Параллельно
ведётся стек открытых скобок: по нему ловится лишняя `)` и незакрытая `(`, а для скобки функции
считается число аргументов (запятые + 1).

### Унарный минус

Лексер не знает, бинарный минус или унарный, — это зависит от контекста. Решение: **минус, стоящий там,
где ожидается операнд** (в начале, после `(`, `,` или другой операции), считается унарным. Проверка
переписывает его в отдельную лексему `Neg`, в ОПЗ она печатается как `~`, чтобы не путать с вычитанием.

Унарный минус — префиксная операция с одним операндом, его приоритет 4: выше `*` и `/`, но ниже
функции. Поэтому `-2*3` = `(-2)*3`, `2*-3` = `2*(-3)`, `2--3` = `2-(-3)` = 5, `--4` = 4,
`-log(3, 9)` = `-(log(3, 9))`. Унарный плюс не поддерживается: `2-+3` — ошибка «два знака операции подряд».

Для `+ - * /` результат не зависит от того, считать `-a*b` как `(-a)*b` или `-(a*b)`, поэтому 4 — просто
естественный выбор (как в C++). Альтернатива «подставить 0 перед минусом» (`-5` → `0-5`) ломается
на `2*-3` → `2*0-3`, поэтому не подошла.

### Стековые приоритеты

Таблица 1 методички, дополненная унарным минусом и функцией:

| Операция | Приоритет |
|---|---|
| `(` `)` | 1 |
| `+` `-` | 2 |
| `*` `/` | 3 |
| унарный `-` | 4 |
| функция `log` | 5 |

Правила (буквы — как в методичке):

- **число** — сразу в выходную строку;
- **a, b) бинарная операция** выталкивает из стека в выход все операции с приоритетом ≥ своего,
  потом кладётся в стек. Из-за того что у `(` приоритет 1, она никогда не выталкивается;
- **c) `(`** — в стек. **Функция и унарный минус** тоже сразу в стек: они стоят перед своим операндом,
  выталкивать им нечего;
- **d) `)`** выталкивает всё до ближайшей `(`, скобки уничтожают друг друга; если под `(` лежит функция,
  она тоже уходит в выход — так функция оказывается сразу после своих аргументов;
- **`,`** выталкивает всё до `(` своей функции (закончился первый аргумент), но саму `(` не трогает;
- **конец строки** — всё, что осталось в стеке, в выход.

Приоритет функции 5 в сравнениях фактически не участвует: функция лежит в стеке под своей `(`, бинарные
операции до неё не доходят, а выталкивает её собственная `)`. Наивысший приоритет обеспечивает само
устройство алгоритма, а 5 записано для полноты таблицы. Если добавить степень `^`, унарному минусу нужно
дать приоритет ниже `^`, чтобы `-2^2` было −4, а не 4.

### Пример

Выражение `(2+3)*-log(2, 8)/4`, вывод `./lab1 --trace` (верх стека справа):

```text
  символ        стек (верх справа)    выход
  (             (
  2             (                     2
  +             ( +                   2
  3             ( +                   2 3
  )                                   2 3 +
  *             *                     2 3 +
  -(унарный)    * ~                   2 3 +
  log           * ~ log               2 3 +
  (             * ~ log (             2 3 +
  2             * ~ log (             2 3 + 2
  ,             * ~ log (             2 3 + 2
  8             * ~ log (             2 3 + 2 8
  )             * ~                   2 3 + 2 8 log
  /             /                     2 3 + 2 8 log ~ *
  4             /                     2 3 + 2 8 log ~ * 4
  конец строки                        2 3 + 2 8 log ~ * 4 /
```

Интересные места: `)` после `8` выталкивает `log` (функция под скобкой); `/` выталкивает и `~` (4 ≥ 3),
и `*` (3 ≥ 3) — так получается левая ассоциативность: `a*b/c` = `(a*b)/c`.

Вычисление ОПЗ `2 3 + 2 8 log ~ * 4 /` за один проход слева направо, как в методичке:

| № | Строка | Действие |
|---|---|---|
| 0 | `2 3 + 2 8 log ~ * 4 /` | r1 = 2 + 3 = 5 |
| 1 | `r1 2 8 log ~ * 4 /` | r2 = log(2, 8) = 3 |
| 2 | `r1 r2 ~ * 4 /` | r2 = −r2 = −3 |
| 3 | `r1 r2 * 4 /` | r1 = r1 · r2 = −15 |
| 4 | `r1 4 /` | r1 = r1 / 4 = −3.75 |
| 5 | `r1` | вычисление окончено |

На стеке: число — положить; бинарная операция — снять два (верхний — правый операнд), положить результат;
`~` — поменять знак у вершины; `log` — снять два аргумента, проверить область определения, положить результат.

## Архитектура кода

Всё в одном файле [`main.cpp`](main.cpp), четыре этапа — четыре функции. Классов нет, только простые
структуры данных: `Token` (лексема), `ExprError` (ошибка с позицией) и `BuiltinFunction` (описание функции).

```text
строка ──tokenize()──> лексемы ──check()──> лексемы (минусы размечены) ──toRpn()──> ОПЗ ──evaluate()──> число
```

| Функция | Что делает | Какие ошибки находит |
|---|---|---|
| `tokenize` | режет строку на лексемы, запоминает позицию каждой | недопустимый символ, некорректное число, неизвестное имя |
| `check` | конечный автомат «ждём операнд / ждём операцию» + стек скобок | всё синтаксическое (см. ниже) |
| `toRpn` | алгоритм Дейкстры, `--trace` печатает таблицу как на рис. 2 методички | не находит: на вход приходит уже проверенная строка |
| `evaluate` | считает ОПЗ на стеке | деление на ноль, область определения функции, переполнение |
| `process` | вызывает этапы, ловит `ExprError` и показывает место ошибки стрелкой | — |

Ошибка на любом этапе — исключение `ExprError{позиция, текст}`. Позиция переводится в номер символа
с учётом UTF-8, чтобы стрелка вставала правильно и под русскими буквами.

Числа хранятся в `double`. После каждой операции проверяется `std::isfinite`, поэтому переполнение не
превращается в `inf`, а выдаётся ошибкой. Деление на ноль проверяется точным сравнением `b == 0`.

## Распознаваемые ошибки

| Ошибка | Пример | Сообщение |
|---|---|---|
| недопустимый символ | `2 & 3`, `2+х` | недопустимый символ '&' |
| некорректное число | `1.2.3`, `. + 1` | некорректное число '1.2.3' |
| число вне диапазона double | `1` и 400 нулей; `0.` и 400 нулей, потом `1` | слишком большое число; слишком близкое к нулю число |
| неизвестное имя | `sin(2)` | неизвестное имя 'sin' (есть только функция log) |
| пустое выражение | строка из пробелов | пустое выражение |
| начало с операции или `)` | `*2`, `)(` | выражение не может начинаться с '*' |
| два оператора подряд | `2+*3`, `2-+3` | два знака операции подряд: '+' и '*' |
| нет операнда после `(` | `(*2)` | после '(' ожидается операнд, а стоит '*' |
| обрыв выражения | `2+` | выражение оборвалось: после '+' ожидается операнд |
| пропущена операция | `2 3`, `(2+3)(4)` | пропущен знак операции между '2' и '3' |
| пустые скобки | `()`, `2*()` | пустые скобки '()' |
| лишняя `)` | `(2+3))` | лишняя ')': для неё нет парной '(' |
| незакрытая `(` | `((1)` | не закрыта '(': не хватает ')' |
| функция без скобки | `log 2` | после имени функции log ожидается '(' |
| неверное число аргументов | `log(2)`, `log(2, 3, 4)` | функция log принимает 2 аргумента, а передано 3 |
| функция без аргументов | `log()` | у функции log нет аргументов |
| пустой аргумент | `log(, 2)`, `log(2, )` | пропущен аргумент функции |
| запятая не в функции | `2, 3`, `(2, 3)` | запятая вне скобок функции |
| деление на ноль | `1/0`, `5/(2-2)` | деление на ноль |
| вне области определения | `log(1, 5)`, `log(2, 0)` | log(2, 0): под логарифмом должно быть положительное число |
| переполнение | `1e200 * 1e200` (записанные цифрами) | переполнение: результат не помещается в double |

Синтаксические ошибки выводятся как «Синтаксическая ошибка», ошибки при счёте — как «Ошибка вычисления»:
во втором случае выражение записано правильно, просто значение посчитать нельзя.

## Встроенная функция и как её заменить

`log(a, b)` — логарифм `b` по основанию `a` (`log(2, 8)` = 3). Функция описана в одном месте —
константа `kBuiltin` в начале `main.cpp`:

```cpp
const BuiltinFunction kBuiltin = {
    "log",                                                         // имя в выражении
    [](double a, double b) { return std::log(b) / std::log(a); }, // формула
    [](double a, double b) -> const char* {                       // область определения
        if (a <= 0 || a == 1) return "основание логарифма должно быть > 0 и не равно 1";
        if (b <= 0) return "под логарифмом должно быть положительное число";
        return nullptr;
    },
};
```

Лексер, проверка, Дейкстра и вычисление берут имя и формулу только отсюда. Чтобы заменить на `pow`,
нужно закомментировать этот блок и раскомментировать готовый вариант прямо под ним:

```cpp
const BuiltinFunction kBuiltin = {
    "pow",
    [](double a, double b) { return std::pow(a, b); },
    [](double a, double b) -> const char* {
        if (a == 0 && b < 0) return "ноль нельзя возводить в отрицательную степень";
        if (a < 0 && b != std::floor(b)) return "отрицательное число нельзя возводить в дробную степень";
        return nullptr;
    },
};
```

и пересобрать `make`. Любую другую функцию двух аргументов (`max`, `root`, …) так же: имя, формула,
проверка. Проверено: после замены `pow(2, 10)` = 1024, `pow(2, pow(2, 3)) - 1` = 255, `log(2, 8)` уже
даёт «неизвестное имя», `pow(0, -1)` — ошибку области определения. Тесты в `tests.txt` написаны под `log`,
для `pow` их нужно поправить.

## Вывод

Калькулятор разбирает строку в три прохода: лексический анализ, синтаксическая проверка конечным
автоматом «операнд/операция» и перевод в ОПЗ алгоритмом Дейкстры, после чего ОПЗ вычисляется на стеке.
Отдельная проверка нужна потому, что алгоритм Дейкстры сам неправильные выражения не отбрасывает.
Функцию в алгоритм удалось встроить без изменения его правил: она кладётся в стек как операция
с наивысшим приоритетом и выталкивается закрывающей скобкой своего вызова, а запятая выталкивает
операции до скобки функции. Унарный минус отличается от бинарного по контексту и тоже обрабатывается
как префиксная операция.
