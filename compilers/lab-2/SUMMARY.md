# ЛР2. Конечные автоматы — коротко

Шпаргалка «на пальцах». Полный отчёт — [README.md](README.md), теория — [THEORY.md](THEORY.md).

## Суть

Конечный автомат — граф: вершины-состояния, стрелки подписаны символами. Начинаем в `q0`, читаем
строку по символу и идём по стрелкам. Строка допускается, если прочитали её целиком и стоим
в конечном состоянии (`f<N>`, на рисунках прямоугольник). Если из какого-то состояния по одному
символу ведут две стрелки, автомат **недетерминированный** (НКА): непонятно, куда идти.
НКА всегда можно превратить в эквивалентный ДКА — **построением подмножеств**: множество
«куда можно попасть» объявляем одним новым состоянием.

## Что делает программа

| Шаг | Что выводится | Как найдено |
| --- | --- | --- |
| Чтение файла | ошибки с номером строки, правила | разбор по позициям `q N , C = q/f N` |
| Описание | состояния, конечные, алфавит, таблица переходов | из правил |
| Детерминированность | все конфликты: `q0 по 'a' -> {q1, q3, q4} (строки 1, 2, 3)` | группы правил с одинаковой парой (состояние, символ) |
| Висячие вершины | недостижимые и тупиковые состояния | обход в ширину от `q0` и назад от конечных |
| Детерминизация | `q6 = {q1, q3, q4}`, правила ДКА в формате файла, таблица ДКА | очередь подмножеств от `{q0}` |
| Разбор строки | ДОПУСКАЕТСЯ / НЕ ДОПУСКАЕТСЯ, путь, где застряли и что ожидалось | проход по ДКА |

## Вывод и откуда он

- `var1.txt` и `var2.txt` — ДКА без висячих вершин. В `var1.txt` автомат расходится с подсказкой
  в комментарии: после `=` пробел не разрешён (`"ab + cd * e = 357"` отвергается на 14-м символе),
  а правило `q9, =q10` позволяет вместо `=` поставить два пробела.
- `var3_nd.txt` — НКА с 4 конфликтами. ДКА: 8 состояний, 13 правил; новые `q6 = {q1,q3,q4}`,
  `q7 = {q1,q5}`, конечные `f2 = {q5,f1}`, `f3 = {q4,f1}`. Совпало с ручным построением.
- Пример из методички (рис. 3) превращается ровно в рис. 4: `{D, f}` — новое конечное с петлёй по `0`.
- Ответы ДКА и прямого моделирования НКА совпали на всех тестовых строках; `make test` — 98 из 98.

## Как рассказывать

> «Программа читает автомат из файла построчно; строку с ошибкой пропускает и сообщает её номер,
> строки с `;` считает комментариями. Потом проверяет детерминированность: группирует правила по
> паре (состояние, символ), и если в группе больше одного правила — это конфликт. Висячие вершины
> ищу двумя обходами в ширину: от `q0` по стрелкам — кто не посещён, тот недостижим; от конечных
> против стрелок — кто не посещён, из того не дойти до конца. НКА детерминизирую построением
> подмножеств, как в методичке: новое состояние — множество старых, переход из него — объединение
> переходов элементов, конечное оно, если содержит конечное. Строку разбираю уже по ДКА».

## Возможные вопросы

- **Чем ДКА отличается от НКА?** В ДКА из состояния по символу не больше одной стрелки, путь
  один. В НКА стрелок может быть несколько, строка допускается, если хоть один путь ведёт в конечное.
- **Как работает построение подмножеств?** Начинаем с `{q0}`. Для множества `D` и символа `a`
  объединяем `t(p, a)` по всем `p ∈ D` — это новое состояние. Повторяем, пока появляются новые
  множества. Конечное — если в множестве есть конечное состояние.
- **Почему ДКА допускает тот же язык?** После чтения `x` состояние ДКА — это множество всех
  состояний, где мог быть НКА. Хоть одно конечное в нём ⇔ НКА допускает `x`.
- **Сколько состояний может быть у ДКА?** До `2^n`, но строим только достижимые из `{q0}` —
  у `var3_nd` из 8 вышло 8.
- **Что такое висячие вершины?** Недостижимые (не попасть из `q0`) и тупиковые (из них не дойти
  до конечного). У тупика может не быть переходов вовсе или быть цикл без выхода (`q5 ⇄ q6` в тестах).
- **Почему `f` может стоять слева (`f2,f=f0`)?** В ДКА конечное множество `{q5, f1}` имеет
  переход по `f`, а на рис. 2 методички из конечного `q4` есть стрелка по `c`. Без `f` слева
  такие автоматы не записать в формате файла.
- **Когда строка допускается, если из `f` есть переходы?** Только когда строка кончилась в `f`.
  Если не кончилась — идём дальше; если дальше стрелок нет — отказ (как в коде методички).
- **Зачем `;`-строки в `var1.txt`?** Это комментарии-подсказки: правило всегда начинается с `q`.
