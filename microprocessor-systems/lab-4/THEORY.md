# THEORY — ЛР4 «CYBERcobra + индивидуальное задание»

Шпаргалка для защиты.

---

## 1. Как работает процессор: алгоритм одного такта

```
1. PC указывает на ячейку памяти инструкций;
2. instr_mem асинхронно возвращает 32-битную инструкцию;
3. Биты инструкции декодируются как поля (J, B, WS, alu_op, RA1, RA2, off/const, WA);
4. Регистровый файл асинхронно отдаёт rf_rd1 и rf_rd2 по адресам RA1, RA2;
5. АЛУ комбинаторно считает alu_result и alu_flag;
6. Мультиплексор WS выбирает источник записи (const / alu_result / sw_i);
7. Сигнал write_enable = !(B | J);
8. По posedge clk_i:
   - в регистровый файл записывается rf_wd (если we=1);
   - в PC записывается PC + (4 или sext(off)<<2 в зависимости от J/B/flag).
```

Однотактный процессор: всё выше происходит **за один такт**.

## 2. Кодировка инструкций

| Тип | J | B | WS | Поля | Что делает |
|---|---|---|---|---|---|
| Вычислительная | 0 | 0 | 01 | alu_op, RA1, RA2, WA | reg[WA] = reg[RA1] {alu_op} reg[RA2] |
| Загрузка const | 0 | 0 | 00 | const[27:5], WA | reg[WA] = sext(const) |
| Загрузка sw_i | 0 | 0 | 10 | WA | reg[WA] = {16'b0, sw_i} |
| Безусловный переход | 1 | x | xx | off, alu_op, RA1, RA2 | PC = PC + sext(off)<<2 |
| Условный переход | 0 | 1 | xx | off, alu_op, RA1, RA2 | if(alu_flag) PC = PC + sext(off)<<2 |

WE = `!(B | J)` — запись только при «нескакательных» инструкциях.

## 3. Почему смещение знакорасширяется и умножается на 4?

- **Знакорасширение**: PC может прыгать как вперёд, так и назад. Если в `off` записано отрицательное число (например, `0xFF` = -1), то после знакорасширения получим `0xFFFFFFFF` = -1, и `PC + (-1)*4 = PC - 4` — прыжок на 1 инструкцию назад.
- **Умножение на 4**: инструкции в памяти лежат с шагом 4 байта. Один шаг `off=1` = одна инструкция вперёд. На уровне RTL умножение на 4 = конкатенация с двумя нулями справа: `{sext(off), 2'b00}`.

---

## 4. Почему `const` всего 23 бита?

23-битная константа в формате `WS=00` инструкции занимает поля `[27:5]`. После знакорасширения покрывает диапазон `[-2²², 2²²-1]` ≈ ±4 миллиона. Произвольное 32-битное значение **за одну инструкцию не загрузить** — нужно составное кодирование (как `lui+addi` в RISC-V). Для моей программы значения 11, 31, 32 — всё влезает в 23 бита, так что одной LOAD-инструкции достаточно.

## 5. Особенности АЛУ для shift-инструкций

В моей реализации (`lab2_alu.sv`):

```systemverilog
ALU_SLL: result_o = a_i << b_i[4:0];
ALU_SRL: result_o = a_i >> b_i[4:0];
ALU_SRA: result_o = $signed(a_i) >>> b_i[4:0];
```

Берётся **только младшие 5 бит** `b_i`. Это согласуется с RISC-V spec — shift на ≥32 бит для 32-битного слова не определён, и срез `[4:0]` гарантирует `shamt ∈ [0..31]`.

**В индивидуальном задании это важно** для граничного случая k=0:
- `r6 = 32 - 0 = 32 = 0x20`
- `b_i[4:0] = 0x20 & 0x1F = 0` → `a << 0 = a`
- результат: `a | a = a` ✓

## 6. Как реализуется rotate-right через АЛУ?

CYBERcobra **не имеет** инструкции rotate — только логические `SLL/SRL/SRA`. Поэтому rotate собирается **из двух сдвигов и одного OR**:

```
ROR(a, k) = (a >> k) | (a << (32 - k))
```

В моей программе это 3 АЛУ-инструкции (плюс подготовка k и 32-k):
- `r7 = SRL(r1, r4)` — правый сдвиг
- `r8 = SLL(r1, r6)` — левый сдвиг
- `r9 = OR(r7, r8)` — склейка

---

## 7. Логика управления PC

```systemverilog
take_branch_or_jump = J | (B & alu_flag);
pc_addend           = take_branch_or_jump ? sext(off)<<2 : 32'd4;
pc_next             = PC + pc_addend;
```

При сбросе (`rst_i=1`) PC ← 0.

## 8. Типичные вопросы преподавателя

**Q: Что произойдёт, если в инструкции с J=1 одновременно WS=01?**
A: Запись не произойдёт, потому что `WE = !(B | J)` жёстко выключается для любого перехода — поведение определено методичкой.

**Q: Почему `out_o = rf_rd1`?**
A: Так требует методичка: «выход out_o подключается к первому порту на чтение регистрового файла». В моей программе последняя инструкция — бесконечный цикл с `RA1 = r9`, поэтому правильный результат удерживается на `out_o`.

**Q: Что если sw_i = 0?**
A: k=0 → ROR на 0 = identity → `out_o = a = 0x0000000B`. Проверено в `check_rotate.sv`.

**Q: Что если sw_i = 31?**
A: ROR на 31 ≡ ROL на 1 → биты [31:1] сдвигаются в [30:0], бит [0] становится [31]. Для a=11 (...01011) → ...10110 (бит [0]=1 уходит в [31]) → `0x80000005`. Stop, это для k=1. Для k=31: бит [0]=1 идёт в [31], бит [31]=0 в [30], ..., бит [1]=1 в [0]. То есть `0x00000016` (биты 1011 уехали на 31 позицию вправо, что эквивалентно сдвигу на 1 влево). Проверено в `check_rotate.sv`.

**Q: Что если sw_i > 31 (например, 32)?**
A: В моей программе первой АЛУ-инструкцией стоит `r4 = sw_i & 31`. Поэтому любое значение нормируется. Это **корректное поведение rotate** (rotate на 32 ≡ rotate на 0).

**Q: Объясните граничный случай `r6 = 32 - 0 = 32` (sw_i=0).**
A: r6 = 32 = `0x20`. В АЛУ подаётся в b_i. Для SLL берётся `b_i[4:0]` = 0 → сдвиг на 0 → `a << 0 = a`. Тогда `r9 = (a>>0) | (a<<0) = a | a = a`. Результат корректен.

**Q: Почему программа не использует ассемблер RISC-V?**
A: Это **псевдо-ассемблер CYBERcobra** — у него своя система команд (5 типов), несовместимая с RISC-V. Полноценный RISC-V появляется только в ЛР7.
