## Часть 1. Реализация процессора CYBERcobra 3000 Pro 2.1

### Цель

Собрать на основе ранее разработанных модулей (АЛУ из ЛР2, регистрового файла и памяти инструкций из ЛР3, сумматора из ЛР1) простейший учебный процессор с архитектурой CYBERcobra. Это даёт интуицию работы программно-управляемых устройств перед переходом к RISC-V.

### Прототип модуля

```systemverilog
module CYBERcobra (
  input  logic         clk_i,
  input  logic         rst_i,
  input  logic [15:0]  sw_i,
  output logic [31:0]  out_o
);
```

### Архитектура (5 типов инструкций)

Структура 32-битной инструкции (от MSB к LSB):

```
 31    30    29:28    27:23     22:18     17:13     12:5         4:0
[J]   [B]   [WS]    [alu_op]   [RA1]     [RA2]    [const/off]   [WA]
```

- **J** — безусловный переход;
- **B** — условный переход;
- **WS** — источник записи в регистровый файл: `00` = константа из инструкции (23 бита), `01` = результат АЛУ, `10` = `sw_i`;
- **alu_op** — код операции АЛУ (см. `alu_opcodes_pkg`);
- **RA1/RA2** — адреса операндов в регистровом файле;
- **WA** — адрес записи;
- **const** — 23-битная знакорасширяемая константа (поля `[27:5]` для WS=00);
- **off** — 8-битная знакорасширяемая константа смещения PC (поля `[12:5]` для J/B).

5 типов инструкций:

1. **Вычислительная** (WS=01): `reg[WA] = reg[RA1] {alu_op} reg[RA2]`
2. **Загрузка константы** (WS=00): `reg[WA] = sext(const)`
3. **Загрузка с внешнего устройства** (WS=10): `reg[WA] = {16'b0, sw_i}`
4. **Безусловный переход** (J=1): `PC = PC + sext(off) * 4`
5. **Условный переход** (B=1): `if (alu_flag) PC = PC + sext(off) * 4`

### Что нужно сделать

- описать модуль `CYBERcobra` с указанным прототипом;
- внутри использовать `instr_mem` (из ЛР3), `register_file` (из ЛР3), `alu` (из ЛР2), `fulladder32` (из ЛР1);
- реализовать PC, мультиплексор источника записи, мультиплексор слагаемого PC, знакорасширения, генерацию `write_enable`;
- проверить через `lab_04.tb_cybercobra.sv` (тестовая программа в `program.mem`).

## Часть 2. Индивидуальное задание (вариант 1)

### Формулировка

> Вычислить **циклический сдвиг вправо** `a >> sw_i`.
>
> Пример: `a = 0...01011`, `sw_i = 0...010`.
> Результат вычислений: `out_o = 110...010`.

Источник: оригинальный репозиторий методички, файл [Индивидуальное задание/README.md](https://github.com/MPSU/APS/tree/master/Labs/04.%20Primitive%20programmable%20device/%D0%98%D0%BD%D0%B4%D0%B8%D0%B2%D0%B8%D0%B4%D1%83%D0%B0%D0%BB%D1%8C%D0%BD%D0%BE%D0%B5%20%D0%B7%D0%B0%D0%B4%D0%B0%D0%BD%D0%B8%D0%B5).

### Что нужно сделать

1. Написать программу на псевдоассемблере CYBERcobra, которая:
   - считывает `sw_i` с переключателей;
   - вычисляет `result = a ROR sw_i` для зашитой в программе константы `a`;
   - выводит результат в `out_o` через бесконечный цикл на последней инструкции.
2. Перевести псевдоассемблер в двоичные коды (вручную или конвертером `cyberconverter`).
3. Записать результат в `program.mem`.
4. Прогнать симуляцию и убедиться, что для нескольких значений `sw_i` процессор выдаёт правильный `out_o`.

### Алгоритм (математика rotate right)

Для 32-битного значения `a` и сдвига на `k` бит:

```
ROR(a, k) = (a >> k) | (a << (32 - k))
```

где обе операции сдвига должны брать только младшие 5 бит счётчика (что естественно для АЛУ RISC-V и нашего ALU из ЛР2: `b_i[4:0]`).

**Граничный случай k=0**: `32-k = 32`, но в АЛУ срез `[4:0]` даст 0 → получим `a >> 0 | a << 0 = a | a = a`. ✓

**Граничный случай k > 31**: программа сначала маскирует `k = sw_i & 31`, поэтому `k ∈ [0..31]`.

### Регистры программы

| Регистр | Назначение |
|---|---|
| `r1` | константа `a = 11` |
| `r2` | значение `sw_i` |
| `r3` | константа `31` (маска `& 31` для k) |
| `r4` | `k = sw_i & 31` |
| `r5` | константа `32` |
| `r6` | `32 - k` |
| `r7` | `a >> k` |
| `r8` | `a << (32 - k)` |
| `r9` | результат: `r7 \| r8` |

### Тестовые случаи (a = 11)

| `sw_i` (k) | Ожидаемый `out_o` |
|---|---|
| 0  | `0x0000_000B` |
| 1  | `0x8000_0005` |
| 2  | `0xC000_0002` |
| 4  | `0xB000_0000` |
| 8  | `0x0B00_0000` |
| 16 | `0x000B_0000` |
| 31 | `0x0000_0016` |

Все эти случаи проверяются автоматически в `check_rotate.sv` (см. README).
