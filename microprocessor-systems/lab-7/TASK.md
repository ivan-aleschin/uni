## Теория

Помимо процессора и памяти, третьим ключевым элементом архитектуры вычислительной машины является система ввода/вывода, обеспечивающая обмен информацией между ядром и разнообразными периферийными устройствами.

Любое периферийное устройство со стороны вычислительной машины видится как набор ячеек памяти (регистров). С помощью чтения и записи этих регистров происходит обмен информацией с периферийным устройством и управление им.

### Адресное пространство

Архитектура RISC-V подразумевает использование совместного адресного пространства. 32-битное адресное пространство разделяется на 256 частей — старшие 8 бит адреса определяют конкретное периферийное устройство, оставшиеся 24 бита — адрес внутри устройства.

Карта устройств (от младших адресов к старшим):

| Старший байт | Устройство |
|---|---|
| `0x00` | Память данных |
| `0x01` | Переключатели (sw) |
| `0x02` | Светодиоды (led) |
| `0x03` | Клавиатура PS/2 |
| `0x04` | Семисегментные индикаторы (hex) |
| `0x05` | UART-приёмник (rx) |
| `0x06` | UART-передатчик (tx) |
| `0x07` | Видеоадаптер (vga) |

> **Важно:** На вход `mem_ready_i` модуля `lsu` подаётся константная единица, так как все предоставленные контроллеры имеют `ready_o = 1` по умолчанию.

### Активация устройства

Каждый контроллер получает сигнал `req_i`, который формируется как конъюнкция сигнала `mem_req` от ядра и бита унитарного (one-hot) кода, соответствующего старшим 8 битам адреса.

## Дополнительные правки `processor_system`

Модуль `processor_system` является модулем верхнего уровня и должен содержать все порты периферии:

```systemverilog
module processor_system(
  input  logic        clk_i,
  input  logic        resetn_i,      // Активный уровень — 0 (отличие от предыдущих ЛР)
  input  logic [15:0] sw_i,
  output logic [15:0] led_o,
  input  logic        kclk_i,
  input  logic        kdata_i,
  output logic [ 6:0] hex_led_o,
  output logic [ 7:0] hex_sel_o,
  input  logic        rx_i,
  output logic        tx_o,
  output logic [3:0]  vga_r_o,
  output logic [3:0]  vga_g_o,
  output logic [3:0]  vga_b_o,
  output logic        vga_hs_o,
  output logic        vga_vs_o
);
```

**Делитель тактовой частоты** — обязательно в начале модуля:

```systemverilog
logic sysclk, rst;
sys_clk_rst_gen divider(
  .ex_clk_i(clk_i),
  .ex_areset_n_i(resetn_i),
  .div_i(5),
  .sys_clk_o(sysclk),
  .sys_reset_o(rst)
);
```

Все внутренние модули (`processor_core`, `data_mem`, контроллеры периферии) тактируются от `sysclk`. Сигнал `rst` — активный высокий.

## Описание контроллеров

### Терминология запросов

**Запрос на запись по адресу `0xАДРЕС`** — совокупность:
- Восходящий фронт `clk_i`
- `req_i = 1`, `write_enable_i = 1`, `addr_i = 0xАДРЕС`

**Запрос на чтение по адресу `0xАДРЕС`** — совокупность:
- Восходящий фронт `clk_i`
- `req_i = 1`, `write_enable_i = 0`, `addr_i = 0xАДРЕС`

> **Важно:** Чтение — синхронное (данные выставляются по фронту `clk_i`, как в `data_mem`). При отсутствии запроса `read_data_o` не меняется.

---

### Контроллер клавиатуры PS/2 (`ps2_sb_ctrl`)

```systemverilog
module ps2_sb_ctrl(
  input  logic         clk_i,
  input  logic         rst_i,
  input  logic [31:0]  addr_i,
  input  logic         req_i,
  input  logic [31:0]  write_data_i,
  input  logic         write_enable_i,
  output logic [31:0]  read_data_o,
  output logic         interrupt_request_o,
  input  logic         interrupt_return_i,
  input  logic         kclk_i,
  input  logic         kdata_i
);
  logic [7:0] scan_code;
  logic       scan_code_is_unread;
endmodule
```

Внутри создаётся экземпляр `PS2Receiver`. Логика работы:

- По каждому фронту `clk_i`: если `keycode_valid_o = 1` → записать `keycode_o` в `scan_code`, установить `scan_code_is_unread = 1`.
- Запрос на чтение `0x00` → выставить `scan_code` на `read_data_o`, обнулить `scan_code_is_unread` (если одновременно не пришёл `keycode_valid_o`).
- Запрос на чтение `0x04` → вернуть `scan_code_is_unread`.
- Сигнал `interrupt_return_i` → обнулить `scan_code_is_unread` (если не пришёл `keycode_valid_o`).
- Запрос на запись `1` по `0x24` → сброс `scan_code` и `scan_code_is_unread` в 0.
- `interrupt_request_o = scan_code_is_unread`.

**Карта адресов:**

| Адрес | Доступ | Назначение |
|---|---|---|
| `0x00` | R | `scan_code` — скан-код нажатой клавиши |
| `0x04` | R | `scan_code_is_unread` — есть непрочитанные данные |
| `0x24` | W (1) | Сброс регистров |

---

### Контроллер семисегментных индикаторов (`hex_sb_ctrl`)

```systemverilog
module hex_sb_ctrl(
  input  logic        clk_i,
  input  logic        rst_i,
  input  logic [31:0] addr_i,
  input  logic        req_i,
  input  logic [31:0] write_data_i,
  input  logic        write_enable_i,
  output logic [31:0] read_data_o,
  output logic [6:0]  hex_led,
  output logic [7:0]  hex_sel
);
  logic [3:0] hex0, hex1, hex2, hex3, hex4, hex5, hex6, hex7;
  logic [7:0] bitmask;
endmodule
```

Внутри создаётся экземпляр `hex_digits`. Логика:

- `hex0`–`hex7` управляют цифрами на 8 индикаторах.
- `bitmask` — битовая маска включения индикаторов (после сброса = `0xFF`).
- Запрос на запись `1` по `0x24` → сброс всех `hex*` в 0, `bitmask = 0xFF`.

**Карта адресов:**

| Адрес | Доступ | Назначение |
|---|---|---|
| `0x00`–`0x1C` | RW | `hex0`–`hex7` (шаг 4 байта) |
| `0x20` | RW | `bitmask` |
| `0x24` | W (1) | Сброс (`bitmask → 0xFF`, остальные → 0) |

## Порядок проверки в Vivado

1. Добавить `lab_13_ps2_hex_instr.mem` как `program.mem` в Design Sources проекта.
2. Запустить тестбенч `lab_13_tb_processor_system` (Behavioral Simulation).
3. В тестбенче отправляются скан-коды через `ps2_send_scan_code` из `peripheral_pkg.sv` (make + break для `0x1C`, `0x32`, `0x21`).
4. Убедиться, что прерывание `interrupt_request_o` возникает после каждого make-кода.
5. Убедиться, что `hex_led_o`/`hex_sel_o` изменяются после обработки прерывания.
6. После успешной симуляции — синтез, имплементация, прошивка платы Nexys A7-100T.
