# Управление качеством программного обеспечения (УКПО)

Лабораторные по метрикам сложности программ. Методички — сканы учебника (МИЭТ, 2024);
для репозитория они сжаты: ч/б 200 dpi, JBIG2 без потерь, обложка и условие оставлены
исходным текстом.

Все лабы делаются на **C#**: преподаватель принимает только его, потому что все формулы
и примеры подсчёта в методичках даны именно для C#. Вариант везде **1**
(компьютер №1, нечётный), задачи берутся «на максимальный балл».

| Лаба | Тема | Задача варианта |
| --- | --- | --- |
| [`lab-1`](./lab-1) | Метрики Холстеда | №1 — функция, переворачивающая строку |
| [`lab-2`](./lab-2) | Метрики Джилба | №18 — табулирование кусочной функции f(x) |
| [`lab-3`](./lab-3) | Метрика Чепина | №21 — чередование 0 и 1 в столбцах матрицы |
| [`lab-4`](./lab-4) | Метрика Маккейба | №7 — шестизначные числа с равными суммами половин |
| [`lab-5`](./lab-5) | Процедурно-ориентированные метрики | №16 — простые числа в интервале [n, m] |
| [`lab-6`](./lab-6) | Метрики Чидамбера и Кемерера (CK) | №1 — «Точка» и «Квадрат», изменение стороны на DR |
| [`lab-7`](./lab-7) | Метрики Лоренца и Кидда | №5 — «Абонент» и «Задолженность» |
| [`lab-8`](./lab-8) | Метрики Абреу (MOOD) | №1 — сетевое напряжение и электроустановки 220/360 В |

В папке каждой лабы:

- `УКПО_ЛРN.pdf` — методичка с теорией, примерами и списком задач;
- `Program.cs` + `LabN.csproj` — решение (консольное приложение .NET 8);
- `README.md` — отчёт по образцу методички: листинг, результаты работы, таблицы, расчёт, выводы;
- `THEORY.md` — подробный пересказ темы для подготовки к защите;
- `SUMMARY.md` — шпаргалка «на пальцах»: суть, выводы, как рассказывать, вопросы, код по блокам
  (пока есть в ЛР1–4).

## Как запустить

.NET SDK 8 подключён через `flake.nix` в корне репозитория. Если стоит direnv,
достаточно один раз разрешить `.envrc` в корне:

```bash
cd ~/repos/uni
direnv allow          # один раз; дальше dotnet появляется в PATH сам при входе в репо
cd software-quality/lab-1
dotnet run
```

Программы читают ввод с клавиатуры, поэтому для быстрой проверки ввод удобно
подавать через конвейер, например `printf '6\n5\n' | dotnet run` в `lab-3`.

Без direnv то же самое делается через `nix develop`:

```bash
cd ~/repos/uni/software-quality/lab-1
nix develop -c dotnet run   # flake.nix nix найдёт сам, поднявшись до корня репо
```

Каталоги сборки `bin/` и `obj/` находятся в `.gitignore`.
