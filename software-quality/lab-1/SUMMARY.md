# ЛР1. Метрики Холстеда — коротко

Шпаргалка «на пальцах». Полный отчёт — [README.md](README.md), подробная теория — [THEORY.md](THEORY.md).

## Суть

Холстед оценивает программу по её тексту, не запуская. Текст делится на два вида «слов»:

- **операторы** — то, что *делает действие* (глагол): `=`, `+`, `<=`, `for`, `if…else`, `return`,
  вызовы `Console.WriteLine()`, а также `;`, `,`, `.`, пары скобок `()`, `{}`, `[]`, объявления `int …`;
- **операнды** — то, *над чем* действие делается (существительное): переменные (`s`, `i`, `result`),
  константы (`0`, `1`, `"Введите строку: "`), имена (`Program`, `Reverse` в объявлении).

Пример: `double x = k / 10.0;` — операторы `double …`, `=`, `/`, `;`; операнды `x`, `k`, `10.0`.

Считаем четыре числа, из них выводится всё остальное:

- **n₁** — разных операторов (31), **n₂** — разных операндов (17);
- **N₁** — операторов всего, с повторами (75), **N₂** — операндов всего (29).

## Метрики

| Метрика | Формула | У нас | Смысл |
|---|---|---|---|
| Словарь n | n₁ + n₂ | 48 | сколько разных «слов» |
| Длина N | N₁ + N₂ | 104 | сколько слов всего |
| Теоретическая длина Ñ | n₁·log₂n₁ + n₂·log₂n₂ | ≈ 223 | какой длины «должна» быть программа с таким словарём |
| Объём V | N·log₂n | ≈ 581 бит | сколько бит нужно, чтобы записать программу |
| Потенциальный объём V* | (n₂* + 2)·log₂(n₂* + 2) | 24 | объём идеальной программы из одного вызова готовой функции |
| Уровень L | V*/V | ≈ 0,041 | насколько близко к идеалу (1 — идеал) |
| Работа E | V/L | ≈ 14 057 | «мысленные усилия» на написание |

n₂* = 6 — число входных и выходных величин: на входе `text` и `answer`, на выходе три строки-подсказки
и перевёрнутая строка.

### Откуда берутся Ñ и V*

- **Ñ** считается только по словарю (n₁, n₂). Это гипотеза Холстеда, проверенная на множестве программ:
  в хорошо написанной программе каждое из n разных слов встречается в среднем примерно log₂n раз.
  Получается «ожидаемая» длина, с которой сравнивают реальную N.
- **V*** считается по n₂*. Холстед представил «потенциальный язык», где задача уже решена готовой функцией:
  программа — одна строка `результат = Функция(входы)`. В ней 2 оператора (вызов и присваивание) и n₂*
  операндов, ничего не повторяется, поэтому n = N = n₂* + 2. Подставляем в V = N·log₂n и получаем V*.

## Какие выводы делаем и почему

Все выводы — это **сравнение реального с ожидаемым или идеальным**.

1. **N против Ñ — есть ли в тексте «мусор».** Если N больше Ñ более чем на 10 %, текст раздут лишними
   повторами, и стоит искать шесть классов несовершенств (лишние присваивания, общие подвыражения и т. п.).
   У нас N = 104 < Ñ = 223, раздутия нет. Методичка в таких случаях пишет «несовершенства отсутствуют».
   Формально нашлась только мелочь: `text` используется один раз, но оставлена ради читаемости.
2. **L = V*/V — насколько компактно решена задача.** L ≈ 0,04, то есть программа в ~24 раза «тяжелее» идеала.
   Это нормально: сам алгоритм — 7 строк, остальное занимает диалог с пользователем. В примерах
   методички тоже 0,02–0,05.
3. **E — трудоёмкость.** Из неё время T = E/18 ≈ 13 минут и прогноз ошибок B = V/3000 ≈ 0,2, то есть
   скорее всего ни одной.

Метрики не бывают «хорошими» или «плохими» сами по себе, они имеют смысл только в сравнении.

## Как рассказывать

> «Задача — функция, переворачивающая строку. Я разбил текст программы на операторы и операнды по правилам
> из примеров методички: вызов метода — один оператор, точка и скобки считаются отдельно, пара фигурных скобок —
> один раз. Получил n₁ = 31, n₂ = 17, N₁ = 75, N₂ = 29. Объём ~581 бит, уровень 0,041 — низкий, потому что
> большая часть текста — ввод-вывод, а не алгоритм. Реальная длина (104) меньше теоретической (223), значит,
> несовершенств нет».

## Возможные вопросы

- **Почему `Console.WriteLine()` — один оператор, а точка и скобки ещё отдельно?** Так считает методичка
  в табл. 1.2: у `Console.WriteLine()`, `.` и `()` там отдельные строки.
- **Почему `Reverse` — и операнд, и оператор?** В объявлении это имя (операнд, как `Main` в табл. 1.3),
  а в строке 19 это вызов, то есть действие (оператор).
- **Что такое λ?** Уровень языка λ = L·V* ≈ 0,99. Им имеет смысл сравнивать только похожие задачи.
- **Откуда Ñ и V*?** См. раздел выше.

## Код по блокам

Номера строк — как в листинге отчёта (без комментариев).

**Функция `Reverse` (4–10) — решение задачи:**

```csharp
4  static string Reverse(string s)          // принимает строку, возвращает строку
6  string result = "";                      // сюда собираем ответ
7  for (int i = s.Length - 1; i >= 0; i--)  // ЦИКЛ: от последнего символа к первому
8  result += s[i];                          // приклеиваем i-й символ
9  return result;
```

Для `"abc"`: i = 2, 1, 0, и result становится `"c"`, `"cb"`, `"cba"`. Для пустой строки i = −1, цикл
не выполняется ни разу, возвращается `""`, поэтому отдельная проверка не нужна.

**`Main` (11–23) — тестирование:**

```csharp
15 do                                                        // ЦИКЛ с постусловием
17 Console.Write("Введите строку: ");
18 text = Console.ReadLine();                                // ввод
19 Console.WriteLine("Зеркальная строка: " + Reverse(text)); // вызов и вывод
21 answer = char.Parse(Console.ReadLine());                  // «ещё раз?»
22 } while (answer == 'y' || answer == 'Y');
```

Слабое место: пустой ответ на «ещё раз?» роняет `char.Parse`. Примеры методички устроены так же.
