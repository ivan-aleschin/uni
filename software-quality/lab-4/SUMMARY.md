# ЛР4. Метрика Маккейба — коротко

Шпаргалка «на пальцах». Полный отчёт с блок-схемой, графом и матрицами — [README.md](README.md),
подробная теория — [THEORY.md](THEORY.md).

## Суть

Маккейб смотрит не на текст и не на переменные, а на **структуру переходов**: программу рисуют как
**граф потока управления**:

- **вершина** — оператор или группа операторов, которые выполняются подряд без развилок;
- **дуга** — переход от одной вершины к другой;
- **вершина ветвления** — где путь раздваивается (`if`, проверка условия цикла).

Сложность = сколько в графе **независимых путей**. Это же число — сколько тестов нужно, чтобы проверить
каждую развилку.

**Цикломатическое число Z = m − n + 2** (m — дуги, n — вершины), или проще: **Z = число ветвлений + 1**.
Порог — 10: если больше, модуль стоит разбивать.

## Наш граф

Задача: вывести шестизначные числа из [A, B], у которых сумма трёх старших цифр равна сумме трёх младших.

| Вершина | Что делает | Строки |
|---|---|---|
| 1 | ввод A, B, подрезка диапазона, `found = false`, `i = from` | 8–15 |
| **2** | `i <= to`? — **ветвление** (условие цикла) | 15 |
| 3 | делим число на половины, считаем суммы цифр | 17–20 |
| **4** | `sumHigh == sumLow`? — **ветвление** | 21 |
| 5 | печатаем число, `found = true` | 23–24 |
| 6 | `i++` | 15 |
| **7** | `!found`? — **ветвление** | 27 |
| 8 | «Требуемых чисел нет» | 28 |
| 9 | конец | 29 |

Дуги (11 штук): 1→2, 2→3, 2→7, 3→4, 4→5, 4→6, 5→6, 6→2, 7→8, 7→9, 8→9.

**Z = 11 − 9 + 2 = 4 = 3 ветвления + 1.**

## Критерии

- **Критерий 1** — минимальный набор маршрутов, который проходит **каждую дугу** хотя бы раз.
  Нам хватает двух: m1 = 1-2-3-4-5-6-2-3-4-6-2-7-9 (длинный, с циклом) и m2 = 1-2-7-8-9 (пустой диапазон).
  p — сколько раз маршрут проходит вершины ветвления: 6 и 2, **S1 = 8**.
- **Критерий 2** — базисные маршруты, их ровно Z = 4: два без циклов (1-2-7-8-9, 1-2-7-9) и два цикла
  (2-3-4-5-6, 2-3-4-6). У каждого p = 2, **S2 = 8**.
- **Метрика Маккейба M = 4.** Критерий 3 (все возможные маршруты) вариант не требует.

Матрица смежности — «из какой вершины в какую есть дуга» (столбец — откуда, строка — куда).
Матрица достижимости — «куда вообще можно дойти». Единицы на её диагонали (вершины 2–6) показывают,
какие вершины лежат на цикле.

## Вывод и откуда он

M = 4, это намного меньше порога 10: программа **структурно простая**. В ней 3 условия (два `if`
и проверка цикла), для проверки по критериям достаточно от 2 до 4 тестов.

## Как рассказывать

> «Я построил граф потока управления: 9 вершин, 11 дуг, 3 вершины ветвления — проверка цикла, сравнение
> сумм и проверка „нашли ли что-нибудь“. Цикломатическое число Z = 11 − 9 + 2 = 4, то же самое даёт
> 3 + 1. По первому критерию хватает двух маршрутов, S1 = 8; по второму — четыре базисных маршрута,
> S2 = 8. M = 4 < 10, сложность низкая».

## Возможные вопросы

- **Почему `i++` — отдельная вершина?** В неё сходятся две дуги (после вывода числа и мимо него), поэтому
  её нельзя слить с соседями. Цикл `for` по правилам методички раскладывается на инициализацию, проверку,
  тело и приращение.
- **Почему маршрут 1-2-7-9 невыполним?** Чтобы пройти 7→9, нужно `found = true`, а без входа в цикл оно
  так и останется `false`. Структурно маршрут независим, а на практике проверяется вместе с циклом.
  Для базиса маршрутов это обычная ситуация.
- **Почему `Math.Max`/`Math.Min`, а не два `if`?** Так короче, и лишних развилок нет. С двумя `if` было бы M = 6,
  это честно отмечено в отчёте.
- **Что значит диагональ матрицы достижимости?** Из вершины можно вернуться в неё же, значит, она на цикле.

## Код по блокам

Номера строк — как в листинге отчёта; «В.» — номер вершины графа.

```csharp
8  Console.Write("A = ");                         // В.1: ввод
9  a = int.Parse(Console.ReadLine());
10 Console.Write("B = ");
11 b = int.Parse(Console.ReadLine());
12 from = Math.Max(a, 100000);                    // обрезаем до шестизначных без if
13 to = Math.Min(b, 999999);
14 found = false;
15 for (i = from; i <= to; i++)                   // В.2 — проверка, В.6 — i++; ЦИКЛ по числам
17 high = i / 1000;                               // В.3: 123456 → 123
18 low = i % 1000;                                //       123456 → 456
19 sumHigh = high / 100 + high / 10 % 10 + high % 10;   // 1+2+3
20 sumLow = low / 100 + low / 10 % 10 + low % 10;       // 4+5+6
21 if (sumHigh == sumLow)                         // В.4: развилка
23 Console.WriteLine(i);                          // В.5: нашли
24 found = true;
27 if (!found)                                    // В.7: развилка
28 Console.WriteLine("Требуемых чисел нет");      // В.8
```

Цифры достаются арифметикой: `/ 100` — сотни, `/ 10 % 10` — десятки, `% 10` — единицы.
