Программа на C# (.NET 8), проект — [`Lab5.csproj`](./Lab5.csproj), исходник —

Тулчейн берётся из flake репозитория: в корне лежит `.envrc` со строкой

```bash

# дальше — из папки лабы

```

Программа спросит `n =`, `m =`, выведет простые числа и их количество, а потом


Если direnv не настроен, то же самое через `nix develop` из папки лабы:

```bash

```

Каталоги сборки `bin/` и `obj/` лежат под `.gitignore` (общие правила в
корневом `.gitignore`), в репозиторий не попадают.

## Реализация программы

Решение построено так же, как в примерах методички: класс с методами, в котором
`Main` в цикле `do ... while` вводит данные, вызывает остальные методы и
предлагает повторить расчёт. Модулей два:

- `isPrime(int x)` — функция из условия задачи: возвращает `true`, если `x`
  простое;
- `Main()` — ввод границ интервала, перебор чисел, вывод простых чисел и их
  количества, диалог повтора.

Полный файл с комментариями — [`Program.cs`](./Program.cs). Ниже тот же текст
без комментариев, с номерами строк — на эти номера ссылаются все расчёты.

| Номер строки | Строка программы |
| ---: | --- |
| 1 | `using System;` |
| 2 | `class Program` |
| 3 | `{` |
| 4 | `public static bool isPrime(int x)` |
| 5 | `{` |
| 6 | `int d;` |
| 7 | `if (x < 2)` |
| 8 | `return false;` |
| 9 | `for (d = 2; d <= x / d; d++)` |
| 10 | `if (x % d == 0)` |
| 11 | `return false;` |
| 12 | `return true;` |
| 13 | `}` |
| 14 | `public static void Main()` |
| 15 | `{` |
| 16 | `int n, m, i, count;` |
| 17 | `char rep;` |
| 18 | `do` |
| 19 | `{` |
| 20 | `Console.Write("n = ");` |
| 21 | `n = int.Parse(Console.ReadLine());` |
| 22 | `Console.Write("m = ");` |
| 23 | `m = int.Parse(Console.ReadLine());` |
| 24 | `Console.WriteLine("Простые числа из интервала [{0}, {1}]:", n, m);` |
| 25 | `for (i = n, count = 0; i <= m; i++)` |
| 26 | `if (isPrime(i))` |
| 27 | `{` |
| 28 | `Console.Write("{0} ", i);` |
| 29 | `count++;` |
| 30 | `}` |
| 31 | `Console.WriteLine();` |
| 32 | `Console.WriteLine("Количество простых чисел: {0}", count);` |
| 33 | `Console.Write("\nДля повтора нажмите клавишу Y: ");` |
| 34 | `rep = char.Parse(Console.ReadLine());` |
| 35 | `Console.WriteLine();` |
| 36 | `} while (rep == 'Y' \|\| rep == 'y');` |
| 37 | `}` |
| 38 | `}` |

Пара замечаний по решению:

- Простое число — натуральное число больше 1, которое делится только на 1 и
  на себя. Поэтому в `isPrime` всё, что меньше 2 (в том числе 0 и
  отрицательные), сразу отсекается (строки 7–8). Интервал при этом может
  начинаться с любого целого, например [−10, 3].
- Делители ищутся от 2 до √x: если у x есть делитель больше корня, то парный
  ему делитель меньше корня и был бы найден раньше. Условие записано как
  `d <= x / d`, а не `d * d <= x`: при x около `int.MaxValue` произведение
  `d * d` переполнило бы `int`.
- Если n > m, цикл в строке 25 не выполнится ни разу, и программа просто
  выведет «Количество простых чисел: 0». Отдельная проверка для этого не нужна.
- Ограничение: m должно быть меньше `int.MaxValue` (2147483647). При
  m = `int.MaxValue` условие `i <= m` всегда истинно, `i++` переполнится и
  цикл станет бесконечным. Для учебной задачи этим можно пренебречь.

## Оценка характеристик программы

### Количество функциональных указателей

Количество функциональных указателей рассчитывают по формуле (3.1.2):

FP = F · (0,65 + 0,01 · Σk_i),  i = 1..14,

где F = f₁ + f₂ + f₃ + f₄ + f₅ — общее количество функциональных указателей с
учётом сложности (формула 3.1.3). Рассмотрим значения f_j для разработанного
решения поставленной задачи:

- **f₁** — количество внешних вводов (вводов данных пользователем) составляет
  **3** (ввод значений переменных n, m и rep — строки 21, 23, 34);
- **f₂** — количество внешних выводов (отчёты, экраны, распечатки, сообщения)
  составляет **6** (вывод диалоговых сообщений — строки 20, 22, 24, 33; вывод
  результатов на экран — строки 28 и 32);
- **f₃** — количество внешних запросов (диалоговых вводов-выводов) равно нулю,
  так как отсутствуют обращения к внутренним и внешним логическим файлам;
- **f₄** — количество локальных внутренних логических файлов равно нулю, так
  как в решении такие файлы отсутствуют;
- **f₅** — количество внешних интерфейсных файлов равно нулю, так как в
  решении такие файлы отсутствуют.

Строки 31 и 35 (`Console.WriteLine()` без аргументов) только переводят курсор
на новую строку и ничего не сообщают пользователю, поэтому внешними выводами
не считаются — так же, как строки 77 и 83 в примере 3.2 методички.

Исходные данные для расчёта количества функциональных указателей сведены в
табл. 1 с учётом сложности обращений к данным. Для внешних вводов, выводов и
запросов обращение к 1–4 элементам данных — низкий уровень сложности, к 5–19
элементам — средний, к более чем 19 — высокий.

**Таблица 1. Исходные данные для расчёта FP-метрик**

| Характеристика | Низкая | Средняя | Высокая | Итого |
| --- | :---: | :---: | :---: | :---: |
| Внешние вводы | 3 × 3 = 9 | 0 × 4 = 0 | 0 × 5 = 0 | 9 |
| Внешние выводы | 6 × 4 = 24 | 0 × 5 = 0 | 0 × 7 = 0 | 24 |
| Внешние запросы | 0 × 3 = 0 | 0 × 4 = 0 | 0 × 6 = 0 | 0 |
| Внутренние логические файлы | 0 × 7 = 0 | 0 × 10 = 0 | 0 × 15 = 0 | 0 |
| Внешние интерфейсные файлы | 0 × 5 = 0 | 0 × 7 = 0 | 0 × 10 = 0 | 0 |
| | | | **Общее количество** | **33** |

Для внутренних и внешних файлов обращение к 1–19 элементам соответствует
низкому уровню сложности, к 20–50 — среднему, к более чем 50 — высокому. В
соответствии с уровнем сложности значение характеристики умножается на
коэффициент сложности; в табл. 1 коэффициенты стоят справа от знака
умножения.

При внешних вводах осуществляется обращение к одному элементу данных (строки
21, 23, 34 — по одной переменной), что соответствует низкому уровню
сложности. При внешних выводах тоже низкий уровень: приглашения в строках 20,
22, 33 не содержат данных, строка 28 выводит один элемент (очередное простое
число i), строка 32 — один элемент (count), строка 24 — два элемента (n и m).
Везде от 0 до 2 элементов, то есть меньше 5. Строка 28 выполняется много раз,
но, как и строка 55 в примере 3.2 (вывод элементов матрицы), каждое её
выполнение обращается к одному элементу, поэтому это один внешний вывод
низкой сложности. Внешние запросы, внутренние и внешние файлы отсутствуют.

F = 9 + 24 + 0 + 0 + 0 = **33**.

Определим теперь значения коэффициентов регулировки сложности k_i, отвечая на
поставленные вопросы. Ответы и значения: «влияние случайное» — 1,
«небольшое» — 2, «среднее» — 3, «важное» — 4, «основное (существенное)» — 5.

1. Какое влияние имеет наличие средств передачи данных? Ответ: влияние
   существенное, следовательно, k₁ = 5. Программа целиком построена на
   обмене данными с пользователем через консоль: без ввода n и m и без вывода
   результата она бесполезна. Во всех трёх примерах методички для таких же
   консольных программ принято k₁ = 5.
2. Какое влияние имеет распределённая обработка данных? Ответ: влияние
   случайное, отсюда k₂ = 1. Всё считается в одном процессе на одном
   компьютере.
3. Какое влияние имеет распространённость используемой аппаратной платформы?
   Ответ: влияние случайное, тогда k₃ = 1. Программа не зависит от
   оборудования, нужен только .NET.
4. Какое влияние имеет критичность к требованиям производительности и
   ограничению времени ответа? Ответ: влияние случайное, поэтому k₄ = 1.
   Жёстких требований ко времени ответа нет.
5. Какое влияние имеет частота транзакций? Ответ: влияние случайное,
   следовательно, k₅ = 1. Один расчёт на один ввод пользователя.
6. Какое влияние имеет ввод данных в режиме реального времени? Ответ: влияние
   основное, тогда k₆ = 5. Данные вводятся с клавиатуры в диалоге, и
   программа ждёт каждое значение, как в примерах методички.
7. Какое влияние имеет эффективность работы конечного пользователя? Ответ:
   влияние среднее, поэтому k₇ = 3. Пользователю нужны понятные приглашения и
   возможность повторить расчёт без перезапуска — это в программе есть.
8. Какое влияние имеет оперативное обновление локальных файлов в режиме
   реального времени? Ответ: влияние случайное, отсюда k₈ = 1. Файлов в
   программе нет.
9. Какое влияние имеет скорость обработки данных (вычислений)? Ответ: влияние
   случайное, поэтому k₉ = 1. Перебор делителей идёт только до √x, и даже
   интервал [1, 1000000] обрабатывается за секунды, причём больше времени
   уходит на вывод 78498 чисел, чем на сами проверки. Требований к скорости
   расчёта в задаче нет, так же как в примерах методички, где везде k₉ = 1.
10. Какое влияние имеют количество и категории пользователей? Ответ: влияние
    случайное, тогда k₁₀ = 1. Один пользователь, разделения по ролям нет.
11. Какое влияние имеет лёгкость инсталляции? Ответ: влияние случайное, отсюда
    k₁₁ = 1. Установка не нужна — `dotnet run` из папки проекта.
12. Какое влияние имеет лёгкость эксплуатации? Ответ: влияние случайное,
    следовательно, k₁₂ = 1. Всё управление — ввод двух чисел и ответ Y/N.
13. Какое влияние имеет разнообразие условий применения? Ответ: влияние
    случайное, поэтому k₁₃ = 1. Программа решает одну учебную задачу.
14. Какое влияние имеет простота внесения изменений? Ответ: влияние
    случайное, тогда k₁₄ = 1. Сопровождение программы не планируется.

Подсчитываем сумму коэффициентов:

Σk_i = 5 + 1 + 1 + 1 + 1 + 5 + 3 + 1 + 1 + 1 + 1 + 1 + 1 + 1 = **24**.

Подставляем в формулу (3.1.2) полученные данные:

FP = F · (0,65 + 0,01 · Σk_i) = 33 · (0,65 + 0,01 · 24) = 33 · 0,89 = **29,37**.

Если считать, что перебор делителей делает скорость вычислений заметным
фактором («влияние небольшое», k₉ = 2), получится Σk_i = 25 и
FP = 33 · 0,90 = 29,70; на выводы это не влияет.

Теперь на основе рассчитанного значения FP можно рассчитывать показатели
качества, производительности, удельной стоимости и документированности. Из
них для учебной программы осмысленно посчитать только качество: при
тестировании (раздел «Результаты работы программы») ошибок не обнаружено,
поэтому DQ = Качество = Ошибки / FP = 0 / 29,37 = 0 ошибок на функциональный
указатель. Для производительности, удельной стоимости и документированности
нужны трудозатраты в человеко-месяцах, стоимость и объём документации, которых
у лабораторной работы нет.

### Связность модулей

Для определения уровня связности модулей воспользуемся процедурой,
приведённой в теоретической части методички (рис. 3.3). Представленное
решение включает два программных модуля. Рассмотрим каждый модуль в
отдельности.

**Метод `isPrime`** определяет, является ли переданное ему число простым.
Модуль реализует единственную прикладную функцию (шаг 1 процедуры — «да»),
следовательно, тип связности — функциональный, **сила связности — 10**. При
вызове выполняется только эта проверка, никаких побочных действий (ввода,
вывода, изменения внешних данных) метод не делает.

**Метод `Main`** осуществляет решение поставленной задачи. Модуль реализует
не единственную прикладную функцию: в нём ввод границ интервала, перебор
чисел с подсчётом простых, вывод результатов и диалог повтора (шаг 1 — «нет»).
Действия внутри модуля связаны (шаг 2 — «да»), и связаны они по данным
(шаг 3 — «да»): введённые n и m задают границы цикла, в цикле накапливается
count, который потом выводится. Порядок действий внутри модуля важен (шаг 4 —
«да»): нельзя перебирать числа до ввода границ и выводить количество до
подсчёта. Тип связности — коммуникационный, **сила связности — 7**.

Почему 7, а не 9, объяснено ниже в разделе «Спорные места»: в примерах
методички `Main` с точно такой же структурой везде получает
коммуникационную связность 7, а буквальный проход по рис. 3.3 дал бы
информационную (9). Здесь у `Main` есть признаки обоих типов, и по правилу
методички («модулю приписывают тип с наименьшей связностью») выбрана 7.

Таким образом, в решении модули с силой связности 10 и 7, что говорит о
достаточно высоком качестве программы и её лёгкой тестируемости: функцию
`isPrime` можно проверить отдельно от ввода-вывода, просто вызывая её с
разными числами.

### Сцепление модулей

Определим уровень сцепления модулей, для чего проанализируем каждый из модулей
разработанного решения на предмет межмодульной связи.

**Метод `isPrime`** является вызываемым, и его единственный входной параметр
`int x` — простой элемент данных. Результат возвращается через `return`
(тип `bool`), глобальных данных метод не использует. Следовательно,
рассматриваемый модуль имеет сцепление по данным (**сила сцепления 1**).

**Метод `Main`** является вызывающим и передаёт вызываемому модулю `isPrime`
параметр, от которого зависит результат его работы (строка 26). Таким
образом, по образцу примеров методички метод `Main` имеет сцепление по
управлению (**сила сцепления 4**). Здесь есть и реальный управляющий флаг,
только идёт он в обратную сторону: значение `bool`, которое возвращает
`isPrime`, прямо решает в строке 26, выводить ли число и увеличивать ли
счётчик.

Сила сцепления программных модулей рассматриваемого решения составляет 1 и 4,
что говорит о достаточно высоком уровне качества программы. Общих
(глобальных) данных у модулей нет, связь идёт только через параметр и
возвращаемое значение.

## Спорные места методички

Методичка в нескольких местах противоречит сама себе. Везде, где приходилось
выбирать, я брал вариант, который ближе к разобранным примерам, потому что
отчёт делается по их образцу.

1. **Коммуникационная или информационная связность у `Main`.** По процедуре
   на рис. 3.3 (шаг 4): если действия связаны по данным и порядок важен, тип
   связности — **информационный** (9), если порядок не важен —
   коммуникационный (7). А во всех трёх примерах про `Main` написано
   «порядок действия внутри модуля важен — тип связности —
   коммуникационный, сила связности — 7». Выбрано 7, как в примерах. Чтобы это
   не было просто подгонкой: у `Main` есть признаки обоих типов — его части
   работают с одними и теми же данными n, m, count (признак
   коммуникационной связности), и результат одной части передаётся в другую
   (признак информационной). Для такого случая в методичке прямо сказано:
   если модулю соответствует сразу несколько типов, ему приписывают тип с
   наименьшей связностью, то есть 7.
2. **Сцепление «по управлению» у вызывающего модуля.** По теории (п. 3
   описания шкалы сцепления) сцепление по управлению — это передача флага,
   который меняет внутреннюю логику вызываемого модуля. `Main` передаёт в
   `isPrime` просто число, это скорее сцепление по данным. Но в примерах
   любой вызывающий метод (`Main`, `sort`, `desk`) получает силу 4 с
   формулировкой «передаёт вызываемым модулям списки управляющих параметров,
   явно влияющих на их работу», в том числе в примере 3.4, где `Main`
   передаёт в `change` строку и символ. Сделано так же, как в примерах.
3. **Арифметика в примере 3.3.** Там f₂ = 4, хотя перечислено пять строк
   (35, 37, 44, 26, 43), а в табл. 3.5 стоит 4 × 4 = 16. И итог
   FP = 38 · (0,65 + 0,01 · 28) = 22,91 неверен: 38 · 0,93 = 35,34. В своём
   расчёте я считал каждую строку вывода, которую перечисляю, и всю
   арифметику перепроверил отдельно.
4. **Вопрос 1 про «средства передачи данных».** В примерах для обычных
   консольных программ без сети на него отвечают «влияние существенное»
   (k₁ = 5). Ответ оставлен таким же, чтобы результат был сопоставим с
   примерами; смысл — консоль является единственным каналом обмена данными с
   пользователем.

## Выводы

1. Разработана программа на C#, которая находит все простые числа в
   интервале [n, m], выводит их и их количество. Проверка на простоту
   вынесена в отдельную функцию `isPrime`, как требует условие; `Main`
   отвечает за диалог с пользователем. Программа проверена на обычных и
   граничных данных (интервал без простых чисел, n > m, отрицательные
   границы, большие числа около `int.MaxValue`), результаты совпали с
   независимым расчётом.
2. В программе 3 внешних ввода и 6 внешних выводов, все низкой сложности;
   файлов и внешних запросов нет. Общее количество функциональных указателей
   с учётом сложности F = 33, сумма коэффициентов регулировки Σk_i = 24,
   откуда FP = 29,37. Это немного больше, чем у примера «Сортировка строк
   массива» (FP = 25,81): Σk_i там та же (24), а разница в F целиком
   из-за того, что у нас больше выводов (6 против 5). Сложность самого
   алгоритма функциональные указатели не учитывают, они считают только
   внешние обращения к данным.
3. FP почти целиком определяется вводом-выводом: 24 из 33 единиц F
   приходятся на выводы. Поэтому для алгоритмических программ вроде этой
   методичка и предлагает метрику свойств (Feature Points) с дополнительной
   характеристикой «количество алгоритмов».
4. Ошибок при тестировании не найдено, поэтому метрика дефектов
   DQ = 0 / 29,37 = 0, то есть заведомо меньше верхней границы нормы
   DQ < 1.
5. Функция `isPrime` имеет функциональную связность (10): она выполняет ровно
   одну задачу и не имеет побочных эффектов. `Main` — коммуникационную (7),
   потому что совмещает ввод, расчёт и вывод, связанные общими данными.
   Модулей со связностью 0–5, которая по методичке говорит о недостатках
   проектирования, нет.
6. Сцепление модулей: `isPrime` — по данным (1), `Main` — по управлению (4).
   Сила сцепления 1 и 4, общих глобальных данных нет, связь идёт только через
   параметр и возвращаемое значение. По шкале методички это достаточно
   высокий уровень качества программы (такой же результат, как в примере 3.4).
7. Улучшить показатели можно было бы, вынеся из `Main` вывод найденных чисел
   в отдельный метод, но тогда он должен был бы либо сам вызывать `isPrime`,
   либо получать массив чисел (сцепление по образцу, 3), и сцепление в
   целом не снизилось бы. Для задачи такого размера двух модулей достаточно.
