# ЛР3. Метрика Чепина — коротко

Шпаргалка «на пальцах». Полный отчёт — [README.md](README.md), подробная теория — [THEORY.md](THEORY.md).

## Суть

Чепин оценивает, насколько программу трудно **понять**, по её **переменным**. Каждую объявленную
переменную относят к одной из четырёх групп по её роли, у каждой группы свой вес:

| Группа | Кто туда попадает | Вес |
|---|---|---|
| **P** — вводимые | исходные данные: вводятся или получаются, дальше только читаются | 1 |
| **M** — модифицируемые | создаются и меняются внутри программы (счётчики, результаты) | 2 |
| **C** — управляющие | от них зависит, куда пойдёт программа (флаги, условия) | 3 |
| **T** — паразитные | объявлены, но не используются | 0,5 |

**Q = P + 2·M + 3·C + 0,5·T**

У C самый большой вес, потому что понять программу — значит понять её ветвления, а их задают
управляющие переменные. T весит мало, но не ноль: мусорная переменная ничего не делает, но мешает читать.

## Наша классификация

| Группа | Переменные | Почему |
|---|---|---|
| P = 3 | `n`, `m`, `a` | размеры вводит пользователь; матрицу после заполнения только читают |
| M = 2 | `i`, `j` | счётчики циклов, постоянно меняются |
| C = 3 | `alternate`, `found`, `rnd` | `alternate` в условии цикла и в `if`; `found` решает, печатать ли «таких нет»; `rnd` — как генератор во всех примерах методички |
| T = 0 | — | неиспользуемых нет |

**Q = 3 + 2·2 + 3·3 + 0,5·0 = 16**

## Вывод

Q = 16 меньше всех примеров методички (20–32), программу **понять несложно**: переменных мало,
роль каждой очевидна. Больше всего дают управляющие переменные (9 из 16), потому что вся логика
задачи — это проверка условий.

## Как рассказывать

> «Метрика Чепина оценивает сложность понимания программы через роли переменных. Исходные данные —
> n, m, a; счётчики — i, j; управляющие — alternate, found и генератор rnd (отнесён к C по образцу методички);
> неиспользуемых нет. Q = 3 + 4 + 9 = 16 — ниже примеров методички, программа простая для понимания».

## Возможные вопросы

- **Почему `rnd` в C, а не в P?** Так во всех примерах методички (генератор `g` в табл. 1.27). По смыслу
  можно отнести и к P, тогда Q = 14 — это указано в отчёте.
- **Почему `alternate` только в C, если она ещё и меняется?** По теории переменную можно учитывать
  в нескольких группах, но в примерах почти всегда каждая стоит в одной. Если добавить `alternate` и `found`
  ещё и в M, будет Q = 20 — тоже разобрано в отчёте.
- **Что будет при N = 1?** Соседних элементов нет, нарушать чередование нечему, все столбцы считаются
  чередующимися.

## Код по блокам

Номера строк — как в листинге отчёта.

**Объявления (6–9) — по ним строится таблица Чепина:**

```csharp
6  int n, m, i, j;              // n, m → P;  i, j → M
7  int[,] a;                    // a → P
8  bool alternate, found;       // оба → C
9  Random rnd = new Random();   // rnd → C (по образцу методички)
```

**Ввод размеров (10–14):** две пары «подсказка + `int.Parse(Console.ReadLine())`», затем `a = new int[n, m]`.

**Заполнение и вывод матрицы (15–23), два вложенных цикла:**

```csharp
15 for (i = 0; i < n; i++)             // ЦИКЛ по строкам
17 for (j = 0; j < m; j++)             // ЦИКЛ по столбцам
19 a[i, j] = rnd.Next(0, 2);           // случайно 0 или 1 (2 не включается)
20 Console.Write("{0,3}", a[i, j]);
22 Console.WriteLine();                // конец строки матрицы
```

**Поиск столбцов с чередованием (24–37) — основная логика:**

```csharp
24 found = false;
26 for (j = 0; j < m; j++)                     // ЦИКЛ по столбцам
28 alternate = true;                           // считаем, что столбец чередуется
29 for (i = 1; i < n && alternate; i++)        // ЦИКЛ вниз, пока не нашли нарушение
30 if (a[i, j] == a[i - 1, j])                 // два соседа равны?
31 alternate = false;                          //   → чередования нет, цикл встанет
32 if (alternate)
34 Console.Write(" " + (j + 1));               // номер столбца с единицы
35 found = true;
```

Чередование значит, что **никакие два соседних элемента не равны**. Как только нашлись равные соседи,
`alternate = false`, и из-за `&& alternate` внутренний цикл сразу останавливается.

**Итог (38–40):** если `!found`, печатается «таких нет».

## Запуск

```fish
cd ~/repos/uni/software-quality/lab-3
printf '2\n4\n' | dotnet run    # маленькая матрица — чаще видно найденные столбцы
```

На больших матрицах чередование встречается редко: вероятность для столбца высотой N равна (1/2)^(N−1),
при N = 6 это около 3 %.
