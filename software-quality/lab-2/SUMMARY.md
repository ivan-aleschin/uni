# ЛР2. Метрики Джилба — коротко

Шпаргалка «на пальцах». Полный отчёт — [README.md](README.md), подробная теория — [THEORY.md](THEORY.md).

## Суть

Джилб считает, что сложность программы определяется **количеством решений** — мест, где программа
выбирает, куда идти дальше (`if`, условия циклов). Чем больше таких развилок на общее число операторов,
тем программу сложнее понять и проверить.

Отличие от ЛР1: операторы мы тоже считаем (L — их общее число по правилам Холстеда), но смотрим
прежде всего на то, **какая доля из них — условия**.

Напоминание: **оператор** — то, что делает действие (`=`, `+`, `if`, `for`, `Console.WriteLine()`, `;`, `()`),
**операнд** — то, над чем оно делается (переменные, константы, имена). Проверка на слух: «сделай что-то» —
оператор, «вот это значение» — операнд.

## Что считаем

| Характеристика | У нас | Смысл |
|---|---|---|
| L | 58 | всего операторов (правила Холстеда из ЛР1) |
| L_if | 1 | операторов `if` |
| L_loop | 1 | циклов (один `for`) |
| **CL** = L_if + L_loop | **2** | абсолютная сложность — число условных операторов |
| **cl** = CL / L | **0,0345** | относительная сложность — доля условий среди всех операторов |
| L_mod | 2 | модулей (`F` и `Main`) |
| N_sv | 1 | связей между модулями (`Main` вызывает `F`) |
| f = N_sv⁴ / L_mod | 0,5 | связанность модулей |
| f* | 0 | доля «ненормальных» выходов (`goto`, `break`) — их нет |

## Вывод и откуда он

Главные числа — CL и cl. На 58 операторов приходится 2 условия, около 3,5 %. В примерах методички
cl от 0,023 до 0,049, мы в том же диапазоне. Значит, **логическая сложность низкая**: программа почти
линейная, одна развилка и один цикл. Модулей два, связь одна, поэтому f = 0,5 тоже мало.

## Как рассказывать

> «Джилб оценивает логическую сложность через насыщенность программы условными операторами. Общее число
> операторов L = 58 посчитано по правилам Холстеда. Условных операторов два: `if` в функции и условие цикла
> `for`, поэтому CL = 2, cl = 2/58 ≈ 0,035 — сложность низкая, в пределах примеров методички. Модулей два,
> связь одна, f = 1⁴/2 = 0,5».

## Возможные вопросы

- **Почему `for` — оператор условия?** В нём есть проверка `k <= 13`, которая решает, продолжать ли цикл.
  Методичка тоже считает циклы в CL.
- **Почему `-4` не операция минус?** В примерах методички отрицательные числа (`-0.5`, `-100`) считаются
  константами, мы сделали так же.
- **Почему шаг по x сделан через целый `k`?** При `x += 0.1` копится ошибка округления: вместо 0 получается
  −0,00000000000000003, вместо 1,0 — 0,9999999999999999. При x = k / 10 каждое значение точное.
- **Что такое f*?** Доля ненормальных выходов (`goto`, `break` из середины). У нас их нет, два `return`
  в `F` — это обычные выходы из функции.

## Код по блокам

Номера строк — как в листинге отчёта.

**Функция f(x) (4–10) — модуль 1:**

```csharp
4  static double F(double x)
6  if (x <= 0.5)                                // РАЗВИЛКА — условие 1 (L_if)
7  return Math.Sin(Math.PI / 2);                // первая ветка, всегда 1
8  else
9  return Math.Sin((x - 1) * Math.PI / 2);      // вторая ветка
```

**`Main` (11–19) — таблица значений, модуль 2:**

```csharp
13 Console.WriteLine("    x       f(x)");                 // шапка
14 for (int k = -4; k <= 13; k++)                         // ЦИКЛ — условие 2 (L_loop)
16 double x = k / 10.0;                                   // x = -0.4 ... 1.3
17 Console.WriteLine("{0,5:f1}  {1,9:f4}", x, F(x));      // вызов F — связь модулей
```
