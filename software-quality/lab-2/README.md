### Почему шаг задан через целый счётчик

Самый очевидный вариант — `for (double x = -0.4; x <= 1.3; x += 0.1)`. Но число 0,1
в двоичной системе точно не представляется, и при многократном прибавлении ошибка
округления накапливается. Я проверил этот вариант отдельно (в репозиторий он не входит),
реальные значения x получаются такие:

| Ожидаемый x | Фактический x при `x += 0.1` | Что печатается |
| :---: | --- | --- |
| 0,0 | −2,7755575615628914·10⁻¹⁷ | `-0.0` вместо `0.0` |
| 0,5 | 0,5 | совпало точно |
| 0,8 | 0,7999999999999999 | `0.8` |
| 1,0 | 0,9999999999999999 | f(x) = `-0.0000` вместо `0.0000` |
| 1,3 | 1,3 | совпало точно, последняя точка не потерялась |

На этом диапазоне таблица «почти» правильная, но только случайно: стоит сдвинуть границы
или шаг, и точка x = 0,5 может оказаться чуть больше 0,5 и уйти не в ту ветку, а последняя
точка — не пройти по условию `x <= 1.3`. Поэтому цикл идёт по целому `k` от −4 до 13,
а аргумент вычисляется заново на каждом шаге: `x = k / 10.0`. Ошибка не накапливается,
x = 0,5 получается ровно (0,5 = 1/2 представляется в двоичном виде точно), точек ровно 18.

### Проверка вручную

- x = 0,5 — граница, по условию x ≤ 0,5 это первая ветка: f = sin(π/2) = 1.
  В таблице 1.0000, то есть граничная точка попала куда нужно.
- x = 0,6 — вторая ветка: f = sin((0,6 − 1)·π/2) = sin(−0,2π) = −sin 36° ≈ −0,5878.
- x = 1,0 — f = sin(0·π/2) = sin 0 = 0.
- x = 1,3 — f = sin(0,3·π/2) = sin(0,15π) = sin 27° ≈ 0,4540.

Видно и то, что вторая ветка нечётна относительно x = 1: f(0,7) = −0,4540 и f(1,3) = 0,4540,
f(0,9) = −0,1564 и f(1,1) = 0,1564. Значения совпадают с выводом программы.

## Словарь программы

При подсчёте общего количества операторов L руководствуемся правилами подсчёта операторов
в метриках Холстеда (ЛР №1), как это сделано в табл. 1.22 и 1.23 методички:

- объявления (`using ...;`, `class ...`, `static double ...`, `static void ...`, `double ...`,
  `int ...`) — по одному оператору на объявление;
- вызов метода (`Math.Sin()`, `Console.WriteLine()`, `F()`) — один оператор на вызов,
  при этом каждая точка `.` и каждая пара круглых скобок `()` считаются ещё и отдельно
  (в том числе скобки в заголовках методов и в условиях `if`/`for`);
- фигурные скобки `{}` считаются парой, в столбце номеров указана строка открывающей
  скобки и в скобках — строка закрывающей, например 5(10);
- кавычки `""` — одна пара на каждую строковую константу;
- конструкция `if () … else …` записывается одной строкой словаря, номера строк
  в виде «строка if (строка else)» — так же, как в табл. 1.22 («17(22)»);
- `-4` в заголовке цикла — это отрицательная константа (операнд), а не операция `-`:
  так же в методичке поступают с `-0.5` (табл. 1.22) и `-100` (табл. 1.23), где минус
  в словарь не попадает; операцией считается только бинарный минус в `x - 1`;
- десятичная точка в литералах `0.5` и `10.0` — часть записи числа, а не оператор `.`
  (обращение к члену). В табл. 1.22 в строку «.» попали номера строк, где есть только
  литералы вида `0.5` и `1.0`, — по-видимому, по ошибке; мы такие точки не учитываем;
- скобки внутри строковой константы `"    x       f(x)"` (строка 13) — это символы
  строки, а не оператор, поэтому в словарь они не входят; то же самое с запятыми внутри
  `"{0,5:f1}  {1,9:f4}"` (строка 17). Аналогичное замечание есть в методичке для строки 28
  рис. 1.7.

`Math.PI` — это операнд (именованная константа); точка в нём, как и в `Math.Sin`, учтена
в строке «.». В отличие от него, `...Length` в ЛР №1 — обращение к свойству, то есть вызов
метода доступа, поэтому там он записан как оператор (как `.Length` в табл. 1.23).

## Оценка характеристик программы

Согласно теории Джилба нужно определить количество операторов условия в исходном тексте.
В C# к ним относятся условный оператор `if` и операторы циклов `for`, `while`,
`do … while` — все они обязательно содержат логическое выражение, от которого зависит
дальнейший ход выполнения программы.

В программе есть:

- один условный оператор `if … else` (строки 6–9, табл. 1, п. 8) — выбор ветки функции;
- один оператор цикла `for` (строка 14, табл. 1, п. 19) — перебор значений аргумента,
  его условие продолжения `k <= 13`.

Других операторов ветвления и циклов нет. Получаем:

- **L_if = 1** — количество условных операторов;
- **L_loop = 1** — количество операторов цикла;
- **L = 58** — общее количество операторов в программе (табл. 1);
- **CL = L_if + L_loop = 1 + 1 = 2** — абсолютная сложность программы;
- **cl = CL / L = 2 / 58 ≈ 0,0345** — относительная сложность программы.

Программа состоит из двух модулей:

- `static double F(double x)` (строка 4) — вычисление значения функции;
- `static void Main()` (строка 11) — основной модуль: перебор аргумента и вывод таблицы.

Значит, **L_mod = 2**. Связь между модулями одна — основной модуль `Main` вызывает `F`
(строка 17). То, что вызов стоит внутри цикла и во время работы выполняется 18 раз,
на число связей не влияет: метрика считается по тексту программы, а не по трассе
выполнения. Поэтому **N_sv = 1**, и отношение числа связей к числу модулей
по формуле (1.2.1):

**f = N_sv⁴ / L_mod = 1⁴ / 2 = 0,5.**

Отношение числа ненормальных выходов к общему числу операторов по формуле (1.2.2).
Ненормальный выход — это передача управления в обход обычной структуры: `goto`
(как в рис. 1.7 методички), `break` или `continue` в цикле, выход из программы
посреди работы, выброс исключения. Ничего из этого в программе нет. Два оператора
`return` в методе `F` к ненормальным выходам я не отношу: каждый из них завершает свою
ветку `if … else` и возвращает результат в точку вызова — это обычный выход из функции,
по-другому метод, возвращающий значение, завершиться и не может. Поэтому **N\*_sv = 0**:

**f\* = N\*_sv / L = 0 / 58 = 0.**

   условиями у неё примерно такая же — это типичная для простых вычислительных задач
   величина, никаких «перегруженных» ветвлениями участков в коде нет.
4. Программа двухмодульная, модули связаны одной связью, f = 0,5 — намного меньше, чем
   в многомодульных примерах методички (20,25 для 4 модулей, 51,2 для 5 модулей).
   Межмодульная структура простая.
5. Ненормальных выходов нет (f\* = 0): управление передаётся только структурными
   операторами, без `goto` и `break`, поэтому текст читается сверху вниз без переходов.
